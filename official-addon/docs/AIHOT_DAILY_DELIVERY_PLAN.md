# AIHOT 每日日报：确认需求与实施验收

## 已确认范围

- 基线：用户提供的 `TurboIO-http-navigation-r7-stopfix-20261012/TurboIO-HTTP-Navigation-unsigned.ipa`；静态核验宿主 1.0.5（201），bundle `com.duriea.turboio.research`，根版新闻标记 `manual-hud-v2`。不切换 focus，不改导航。
- 内容：AIHOT 官方每日一期，仅眼镜文字阅读。已核实匿名 RSS 与官方详情同源；官网建议定时程序使用 JSON，首版直接按日期请求官方详情，保留 RSS 来源地址而不重复请求只有目录的索引。不依赖 TinyFish 或模型改写，不建设通用 MCP 管理或通用 RSS 阅读器。
- 稿件必须自动进入官方提词器稿件列表并重启保留；仅 TurboIO 库或传稿缓存不符合需求。
- 北京时间（Asia/Shanghai）每日 09:00 起，App 运行时自动尝试；前台恢复后补发当天任务，不承诺系统挂起时精确定时。
- 日报未发布、未连接等确定失败，10 分钟后再试；遵守服务端 Retry-After，不并发洪泛。不抢占其他提词会话。
- 当天完整收稿与开始阅读业务确认成功后持久化完成；当天版本更新、暂停、退出、重启不再自动发送。手动重读另行操作。
- 当日有效，跨日不追播旧稿。昨日结果未知的眼镜会话仍需安全处理，不能因换日而认为空闲。
- 保留现有手动新闻功能；自动路径与其互斥，避免争抢眼镜。
- 官方入库与眼镜发送分别持久化、分别去重。已提交但结果不明时进入待确认，不盲目再次创建稿件或重复播放。

用户已明确确认上述范围理解一致。官方自动入库未验证，不得将手动导入成功当作自动调用已实现。

## 已有证据

### 官方手动导入

用户截图明确显示“导入文稿”“新建文稿”，支持 1 MB 以内 txt、docx、pdf。公开测试稿“TurboIO 日报入库测试”、校验码 7392 已在官方编辑页出现；用户进一步明确确认完全关闭并重启后仍在官方列表、正文正确。

静态 IPA 包含官方 Dart 新建/导入/保存与 metadata/file/list 相关标识，但未证明原生扩展具有可调用的保存入口。不得猜测数据库结构或仅向目录放文件。

### 日报来源

- RSS：`https://aihot.news/feed/daily.xml`，GUID `daily-YYYY-MM-DD`；description 只有导语与目录，不是完整阅读稿。
- 官方详情：`https://aihot.news/api/v1/dailies/{date}`，schemaVersion 1，report.date 为北京时间版期。
- 详情含 lead、sections.items 的 title/summary/source/links、flashes 的 title/source/links；快讯无 summary，不补造。
- 计划 08:00 发布，但已观察晚至下午的有效期次；09:00 无当期应等待，不能冒充昨日。
- 官方明确的“今日安静，无大事发生”是有效日报，不能将空栏目误判失败。
- ETag/304 必须和已校验的 URL/date 缓存一起使用；无缓存的 304 不是成功内容。
- 保留 canonical/original 与署名；官方摘要不是第三方全文。个人非商业/内部读取和必要私有缓存与公开再分发授权不同，公开产品仍需核对使用规则。

## 实施任务与门槛

1. task-6：独立 AIHOT 日报采集/校验/确定性转稿模块及离线测试，不碰现有 UI 或眼镜代码。

3. 门槛通过后，派发根版生命周期/调度、持久账本、官方导入和眼镜事件接线。门槛不通过则明确报告阻碍，不以缓存替代。
4. 自检后由调度者读关键 diff、复跑测试、检查权限/隐私/失败恢复，再独立输出新包；原 IPA 不覆盖。真机官方列表与眼镜播放未验项必须标明。

## 状态规则

官方稿件状态与眼镜传输状态不可合并为一个布尔值。至少区分：当日待取稿、已取稿、入库待确认、已官方入库、发送待确认、当日完成、过期。

- 外部提交前先持久化尝试标识；账本写失败不得继续提交。
- 官方入库成功需要稳定稿件标识与列表回读关联，不能凭文件存在确认。
- 发送完成必须关联同设备/同一次尝试的完整收稿与开始回执；started 提交标记或 playing 的泛化状态不足以归属日报完成。
- 已完成的自动路径硬拦截；未知提交恢复后不创建新尝试。无可靠设备查询/幂等接口时不承诺端到端恰好一次。
