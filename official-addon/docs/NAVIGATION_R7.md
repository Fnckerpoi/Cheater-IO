用户本轮确认V6已验收。R7保留独立六入口、自动地图/我的位置、同进程重启、后台持续与正常结束链，不刷固件；新节奏/自动在线算路仍待真机验证。

## V6实际节奏和R7区别

| 层级 | V6 | R7真实routeScoped |
| --- | --- | --- |
| HUD内容变化提交门槛 | 最短3.2秒 | 最短0.5秒 |
| 字幕Core防洪门槛 | 最短3秒 | 最短0.5秒 |
| 重复文字 | 不重复；约10秒有界重绘 | 保持去重和约10秒续显，不每500ms重发同一内容 |
| 传输未完成 | 一笔在途，最新帧合并 | 保持；收到完成回调后发送最新合法帧，不积累旧指引 |
| 前台调度守卫 | 1秒 | 100ms检查，500ms两层门槛仍生效，不是100ms发字 |
| 原诊断/模拟/自定义旧调用 | 3.2/3秒、240秒/80帧 | 不放宽，只真实高德路线改节流 |

500ms是可获得执行机会时的**最短提交间隔/调度目标**，不是恒定2HzGPS或镜片端到端刷新保证。高德回调未变化、蓝牙SDK回调慢、系统后台调度暂停时会更慢；不伪造指引。手机转向帧→SDK提交→蓝牙写入→眼镜渲染分别有延迟，本应用只知道提交与SDK完成，不把完成当镜片渲染ACK。

转向/道路/距离相同会去重；现有米数>=50仍按10米向下取整（展示取整不是GPS采样频率），因此站立或短距离移动不一定每半秒见数字变化。过期15秒改中性提示不重绘旧距离。状态含submitMinInterval=0.5、lastSubmitAt、sourceAge供脱敏诊断，诊断文件5秒合并落盘避免每帧磁盘写堵塞发送；非route诊断/异常状态仍即时记录。

**不能据此认定满足电动车骑行安全。** 当前“骑行”仍使用已接入的AMapNaviRideManager，不因提高发送频率就变成电动车专用道路/限制策略。先静止或安全步行验证，勿边骑行/驾驶/过马路边测试，不以实验镜片替代观察和成熟导航产品。

## 自动规划

1. 无目的地时只浏览/搜索，切方式不凭空生成终点。
2. 选择搜索结果、地图点击/长按终点或中心设终点后，250ms防抖再自动规划，用手机当前位置与所选步行/骑行/驾车对应引擎。
3. 未开始导航时切出行方式，旧ready路线作废；算路中快速更换也先取消/退旧引擎再对最新意图算路，不把旧异步结果当新路线。
4. 旧引擎或选择弹层未就绪时有界等待最多约4秒，过界提示不循环重试；定位未决定时明确请求使用期间权限，授权后自动续行，与地图自动定位的授权请求不重复弹。
5. 地图/Key/SDK隐私未就绪、拒绝定位/后台/离页或停止时不会自动算路或开始。失败不持续轮询服务；选择终点/切方式可手动触发新的意图重试。
6. **自动规划不自动开始导航。** 算路成功后“开始步行/骑行/驾车”才可用，仍由用户点开始、确认镜片空闲，开始成功后自动显示。
7. 已开始的真实路线仍锁住方式和终点修改，先结束再切方式；不会骑行中静默换引擎。

普通页面移除“规划路线”按钮，内部旧离线夹具控件未加入视图，仅用于兼容主机测试。页面版本为 `nav-subtitle-v7-auto-plan`，更多诊断“导航状态 · v9 自动规划/500ms目标”。
