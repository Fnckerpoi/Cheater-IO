## 1. 选对版本与路线

### 1.1 V1 与 V2 不要混用

| 路线 | 运行位置 | 配对与适用场景 |
| --- | --- | --- |
| V1 独立 App / SDK | 自己的独立客户端 | 与官方客户端切换时按项目说明处理解绑、系统蓝牙与重新配对 |
| 普通 iOS V2 | 使用者准备、合并与签名后的官方 App 副本内 | 复用宿主已有连接、ASR 和业务流程；打开 TurboIO 不需要换另一套客户端 |
| Android 扩展 | 独立 Android 适配工程 | 不能用 iOS dylib、IPA 或签名工具处理；见第 12 节 |
| FOCUS / TNV1 / TMU1 / TWR1 | 特定手机构建与实验固件配套 | 独立版本和精确门禁，不是普通 V2 开关，不能混刷 |

**先记住三个不同的版本号：** Turbo-IO 路线版本、官方手机 App 版本、眼镜固件版本，互不替代。

### 1.2 普通 iOS 宿主兼容表

| 官方 App 版本 | Build | 主程序 Runner UUID |
| --- | --- | --- |
| 1.0.5 | 201 | `748fd301da603095a2449bd0558faca5` |
| 1.0.4 | 195 | `261c8e78f9553d7d85f713b9082972cf` |
| 1.0.2 | 67 | `eeea85e54114313cb65173c90a6b5d3c` |

普通公开目标 Bundle ID 为 `com.rayneo.venus.pub`；任意 IP HTTP 专用研究目标为 `com.duriea.turboio.research`，二者构建和打包配置不可互换。HTTP 专用预合并流程要求原厂输入 **1.0.5 / 201**。

- 同样的版本号仍需匹配 Build 和 UUID；未知版本停止，不改版本号强行通过。
- 输入需合法可用、未加密、thin arm64；普通 App Store 加密 IPA 不能直接合并。
- UUID 是兼容性约束，不是应用来源可信证明。
- 最新普通适配文档基线为官方 1.0.5（201）与原厂 Strix OS 1.0.4.12；不能外推所有设备及固件。

**依据：** [V2 主说明](../README.md)、[1.0.5 适配](COMPATIBILITY_105.md)、[任意 IP HTTP 分支](LOCAL_HTTP_RESEARCH.md)。

### 1.3 功能可用性速查

| 功能 | 默认普通构建 | 额外条件 / 当前边界 |
| --- | --- | --- |
| TurboIO 入口、自有模型、个人资料 | 包含 | 合法兼容宿主、签名；模型自己配置 |
| 本机回答朗读 | 包含 | 蓝牙音频路由；实际听感单独验收 |
| 云端 TTS、TinyFish | 包含配置入口 | 各自的服务 Key、网络与权限 |
| 新闻提词器 | 包含 | 模型与搜索、提词通道准备；非实时字幕 |
| 录音 / 转写 / 智记导出 | 包含研究入口 | 仅覆盖实际存在或明确开启后收到的数据 |
| 知识库 / Codex | 包含手机入口 | 自建 HTTPS 桥接服务、独立令牌、只读资料 |

| 任意 Agent 控制电脑 / 写知识库 | **没有通用执行能力** | Agent 下拉菜单不代表执行器已接通 |

## 2. 认识入口与界面

### 2.1 从官方首页进入 TurboIO

1. 打开已签名安装的研究副本，按官方流程登录、连接眼镜。
2. 底栏前四项保留官方导航，第五项 **TurboIO** 打开扩展面板。
3. 进入面板后，底部有 **模型 / 新闻 / 资料 / 诊断** 四个分区。
4. 用右上角 **关闭** 回到同一官方宿主。**关闭面板不等于停止模型请求、新闻更新或采集；先在相应功能里点停止。**

### 2.2 找不到第五项时

- 等待官方主页四项导航完整出现；登录页、键盘、弹层等场景可能不展示适配层。
- 匹配不明确时保留官方底栏，并可能显示备用 **研究** 按钮。
- VoiceOver 开启时回退官方导航。
- 长按 TurboIO 约 **1.5 秒**可在本次运行临时恢复官方底栏；重启后重新启用适配。
- 不要因为入口没出现就反复解绑或刷固件；到 **诊断 → 适配与回调** 检查版本与状态。

## 3. 首次准备、构建与安装

> 已经安装且模型可用：跳过本节。所有命令从仓库根执行；路径和签名参数使用你自己的值，不照抄别人的证书或设备标识。

### 3.1 准备清单

- Mac、完整 Xcode，已完成首次运行与 SDK 安装。
- Node.js **22.16+**、Python 3；`node`、`python3` 可从当前终端找到。
- 合法可信的兼容原始 `Runner.app`，保留未修改备份。
- 自己的有效开发签名与描述文件，或自己决定使用的第三方签名工具。
- iPhone 信任电脑，按系统要求启用开发者模式与信任签名。
- 模型、搜索、TTS、高德、知识库令牌按需要单独准备；没有统一的“TurboIO 总 Key”。

先检查环境：

```sh
xcode-select -p
xcrun --sdk iphoneos --show-sdk-path
node --version
python3 --version
```

Xcode 路径未选对时，在本次终端指定实际安装路径：

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
```

`node: command not found` 时激活自己已安装的 Node 版本或将其 `bin` 放入本次终端 PATH，不必修改项目源码。

### 3.2 路线 A：普通 HTTPS 扩展

```sh
bash official-addon/test.sh
node --test official-addon/macho-embed.test.mjs official-addon/package.test.mjs
bash official-addon/build.sh embedded
```

**预期产物：** `official-addon/build/embedded/TurboIOPrivateAddon.dylib`。

这是动态库，不是可安装 App。默认没有模型 Key、没有高德 SDK、没有局域网 HTTP opt-in。不要拿它替代已跑通 HTTP 的专用库。

#### 使用自己的证书在本机合并并签名

```sh
node official-addon/package.mjs \
  --app /absolute/authorized/Payload/Runner.app \
  --addon /absolute/Turbo-IO/official-addon/build/embedded/TurboIOPrivateAddon.dylib \
  --profile /absolute/private/development.mobileprovision \
  --identity YOUR_CERTIFICATE_SHA1 \
  --device YOUR_DEVICE_ID \
  --out /absolute/private/new-v2-output
```

1. `--out` 必须是**不存在的新目录**，输入副本不被原地修改。
2. 工具先校验宿主、加密、架构与重复嵌入，再加入加载命令及动态库、重签嵌套代码与主应用。
3. 检查输出的 `Payload/Runner.app` 与 `TurboIO-local-only.ipa`；仅本机保管。
4. 用自己的设备标识安装：

```sh
xcrun devicectl device install app --device YOUR_DEVICE_ID \
  /absolute/private/new-v2-output/Payload/Runner.app
```

**成功判据：** 安装被接受 → App 能启动 → 登录正常 → 连接正常 → TurboIO 入口正常，五项分别验证。签名通过不等于眼镜功能通过。

### 3.3 路线 B：任意 IP HTTP 研究构建（含公网）

> 2026-10-10 的新研究版本支持任意数字 IP，包括公网，并保留原局域网地址兼容。HTTP 的 Key、问题、个人资料与上下文会明文传输；公网尤其不安全，优先 HTTPS。知识库与转写整理的独立 HTTPS 校验不变。

配置示例（公网使用文档保留地址，不是可直接调用的真实服务）：

```text
http://192.168.31.101:8080/v1/chat/completions
http://203.0.113.20:9000/v1/chat/completions
http://[2001:db8::20]:1234/v1/chat/completions
```

- HTTP 只支持标准数字 IPv4 / 方括号 IPv6，不接受域名、简写 / 八进制 IPv4 或 IPv6 zone ID。HTTPS 仍可使用域名。
- 端口 1–65535，省略为 80；规范路径以 `/chat/completions` 结尾，无编码、点段或双斜杠。
- 不接受 URL 内嵌用户名密码、查询参数、片段或重定向。更换地址重新输入 Key、确认风险并测试；安装新版本后换 IP / 端口无需再次构建。
- **为动态 HTTP 地址，预合并器放宽整个研究 App 的 ATS，不是仅放宽插件**；系统证书默认校验没有关闭。详见 [网络配置边界](LOCAL_HTTP_RESEARCH.md)。
- 手机已有旧固定 IP 包不会自动获得新策略，需先重新构建、预合并、签名安装。

```sh
TIO_LOCAL_HTTP_ENABLED=1 bash official-addon/build.sh embedded com.duriea.turboio.research
```

**预期产物：** `official-addon/build/local-http/TurboIOPrivateAddon.dylib`。保持此目标标识，不混用默认 `build/embedded/`。

先生成已合并、**未有效开发签名**的 IPA：

```sh
python3 official-addon/local_http_package.py \
  --app /absolute/authorized/Payload/Runner.app \
  --addon /absolute/Turbo-IO/official-addon/build/local-http/TurboIOPrivateAddon.dylib \
  --node /absolute/node22/bin/node \
  --out /absolute/private/new-local-http-output
```

**预期产物：** `TurboIO-LocalHTTP-unsigned.ipa`。它是签名输入，不可直接当已签名应用安装。

#### 用 Sideloadly 签名安装预合并包

1. 连接并解锁 iPhone，让签名工具识别自己的设备。
2. 载入上一步的未签名 IPA，使用你自己的 Apple 账号，账号及令牌不写入手册或仓库。
3. 取消 **Use automatic bundle ID**，保持 `com.duriea.turboio.research`，应用名为 `TurboIO Research`；不改原始版本号或机型限制。
4. **取消 Inject dylibs/frameworks，并清空外部 dylib 条目。** 此 IPA 已含一份扩展，再注入会造成重复。
5. 不启用 Cydia Substrate、Substitute 或 Sideload Spoofer。
6. 签名安装；如遇要求删除旧 App、撤销证书或解除限制，先停止并排查，不为了完成安装丢掉唯一可用副本。

**分清两类输入：** 原始 IPA 加外部 dylib 是“工具负责注入”；预合并 IPA 是“工具只签名”。同一次安装只能采用其中一种，不能叠加。

**依据：** [普通构建](../build.sh)、[本机签名工具](../package.mjs)、[HTTP 构建与打包](LOCAL_HTTP_RESEARCH.md)、[预合并器](../local_http_package.py)。第三方工具 UI 随版本变化，核对同义选项而不是盲按旧截图。

## 4. 更新、续签与回退

### 4.1 更新前先确认自己是哪种构建

记录：原厂输入版本、实际安装目标 Bundle ID、所用 dylib 路径、是否已预合并、签名账号与签名方式。

1. 先停止问答、录音、提词、智记和传输；固件升级状态不明时不强停 App。
2. 备份必要配置与导出文件，保留上一个已验证包及未修改原厂输入。
3. 从**原始兼容输入**重新生成一个新输出，不在已合并 App 上再次合并。
4. 使用同一签名账号与应用标识尝试覆盖更新；不要先卸载。
5. 若采用预合并包，保持第三方工具的额外注入关闭；检查自动续签缓存也换成新包。
6. 更新后依次检查启动、配置、连接、合成 API 测试、镜片文字、朗读与退出。

### 4.2 更新本轮固定深色底栏

普通 V2 的 `HomeTabBridge.m` 已固定深色并弱化高光；手机现有安装不会自动获得源码变化。

- 普通 HTTPS 用户：重新执行路线 A 构建与打包。
- **你当前 HTTP 用户：重新执行路线 B，使用 `build/local-http/` 产物；新库包含固定深色底栏与任意 IP HTTP。不能直接用普通库覆盖，否则会失去 HTTP 模型入口。预合并器也需使用当前版本以同步 ATS 配置。**
- FOCUS 是独立源码，本轮普通底栏修改不自动同步到它。
- 保持五项原点击逻辑不变；安装后核对系统浅色时底栏仍为深色。尚未承诺与官方原始底栏像素级一致。

### 4.3 签名到期与无线续签

1. 以自己的签名方式显示的有效期为准；本机现有免费研究签名记录为 7 天，不代表所有账号类型相同。
2. 若使用 Sideloadly 自动刷新，确认应用已登记为自动刷新、缓存为最新 IPA、额外注入数为 0。
3. 无线方式先在 Finder 开启 **连接到 Wi-Fi 时显示此 iPhone**，拔线后确认电脑仍可发现设备。
4. 保持电脑开机、联网、后台续签程序运行；账号登录失效、休眠、隔离网络都会影响刷新。
5. 长时间离开电脑前可以手动刷新，刷新后再测模型配置。

本机已有一次后台菜单手动触发无线刷新及刷新后 API 测试成功记录；**无人值守到期前自动刷新尚待观察**。不要删除研究 App 来“续签”。

### 4.4 回退

- 优先重新签名安装上一个已验证、同目标标识的包；不修改眼镜固件，不先删 App。
- 想停止自有回答：选择 **官方默认**；App 重启也会复位回答模式。
- 想临时停用覆盖底栏：长按 TurboIO 约 1.5 秒。
- 回退到默认 HTTPS 构建会拒绝所有 HTTP 地址，这是预期安全边界而不是模型故障。

## 5. 日常问答与自有模型

<img src="model-preview.png" width="300" alt="模型与对话预览：Agent、知识库、当前回答方式、接口与密钥" />

*图 2：模型页的位置参考。浅色研究面板不代表官方主界面有主题切换。*

### 5.1 已经跑通用户的每日最短步骤

1. 打开研究副本，确认眼镜连接和音频路由。
2. 进入 **TurboIO → 模型 → 当前回答方式**，核对是否为 **自定义模型（实验）**；重启后通常回到官方默认，需重新选择。
3. 如更新或网络变化，先去 **诊断 → 测试模型接口**。
4. 回官方主界面，按官方唤醒 / 问答方式说一句普通聊天问题。
5. 分别看镜片正文、听声音，并用 **退下吧 / 关闭 / 没事了 / 关闭窗口** 等完整短句测试退出。
6. 用服务端日志核对本轮请求，不公开日志正文、Key 或历史。

**不要重复安装、解绑或更改模型 URL，除非确实需要更新或迁移服务。**

### 5.2 第一次配置模型

路径：**TurboIO → 模型 → 接口与密钥**。

| 字段 | 填什么 | 常见错误 |
| --- | --- | --- |
| 接口地址 | 完整 OpenAI-compatible `…/chat/completions` URL | 只填域名或 `/v1`；默认构建填 HTTP |
| 模型名称 | 服务实际提供的模型 ID | 照抄别人的模型名，服务并未提供 |
| API Key | 自己服务的有效凭据 | 用搜索 Key / TTS Key 代替；留空导致无法请求 |

1. 填入三项，确认保存。当前 HTTP 分支还会要求明文风险确认；取消不保存。
2. 保存会恢复官方模式，不自动接管。
3. 到 **诊断 → 测试模型接口**；测试使用合成问题，不携带真实聊天历史。
4. 测试通过后在 **当前回答方式** 选择自定义模式。
5. 用普通聊天问题实测，不以官方技能命令或待办作为首个模型验证题。

接口要求支持兼容请求、流式 `text/event-stream` 与完成标记；默认扩展拒绝 HTTP，专用例外见第 3.3 节。是否接受“关闭深度思考”的扩展参数取决于服务，先不开，确认兼容后再使用。

### 5.3 回答模式和官方链路的真实关系

| 模式 | 用途 |
| --- | --- |
| 官方默认 | 保留官方回答路径，分层验证连接 / ASR / 业务 |
| 随机字符串验收 | 合成文字接管，不调用自有模型 API |
| 自定义模型（实验） | 本轮符合条件的普通聊天回包出现后，请求自有模型并复用官方呈现 |

- 普通 V2 **不替换官方 ASR**，本地模型回答不等于语音离线或完全绕开官方云。
- 每轮需要合格的本轮官方普通聊天回包；未知业务、离线或技能结果保留官方处理。
- **先完成另一次官方完整问答不是源码硬性要求。** 为排障先验证官方问答仍是合理步骤。某些 UI 提示比当前执行机制保守，详见机制文档。
- 接口测试成功、服务收到请求、镜片显示、朗读和退出是不同层次，分别验收。

**依据：** [模型配置 / 测试](../Addon.m)、[请求与流解析](../Core.m)、[当前接管机制与旧提示更正](MODEL_TAKEOVER_MECHANISM.md)。

### 6.2 本次对话上下文

1. 在 **模型 → 本次对话上下文** 查看状态。

3. 点击清空并确认：取消正在进行的自有请求、清空扩展内存历史、恢复官方模式。
4. 清空扩展历史不会删除官方记录；模型供应商或其他服务端日志需分别管理。

### 6.3 先用本机朗读验证声音

1. 进入 **模型 → 回答同步朗读**，开启开关。
2. 在 **朗读引擎** 选择 **本机朗读 · 默认，无需 Key**。
3. 点击 **播放测试语音**，确认声音来自眼镜音频路由，而不是仅手机扬声器。
4. 再各测试一次官方与自有回答的完整朗读。
5. 没声音先查蓝牙音频、路由、系统音量和开关，不先重签或重新配对。

本机 TTS 使用 iOS 语音，不需要云端 Key；不能将已有云端听感结果算成本机听感验收。

### 6.4 可选阿里 Flash 云端 TTS

1. 在 **阿里 Flash TTS 配置** 填自己的有效 WSS 服务地址和独立 TTS Key。
2. 在朗读引擎选对应云端模式，检查开关是否开启。
3. 先播放测试语音，再做实机问答。
4. 云端会收到回答文字，可能涉及费用；不用模型 Key 代替 TTS Key。
5. 路由异常、断网、锁屏和打断分别验证，不承诺任何连接状态都能出声。

### 6.5 语音退出

在 **模型 → 语音退出** 核对开关。用完整短句“退下吧”“关闭”“没事了”“关闭窗口”测试；无法退出时使用眼镜实体控制，不连续开启新会话覆盖旧会话。退出能力需当前宿主停止入口通过检查。

## 8. AI 新闻与提词阅读

> 此功能用 TinyFish 与自有模型生成带来源稿件，再使用眼镜内置提词器。不是实时字幕，不启动麦克风，不是镜片显示网页。

### 8.1 首次准备

1. 先完成模型测试与 TinyFish 配置。
2. 进入 **TurboIO → 新闻**。
3. 核对顶部 **眼镜准备** 状态；未准备时点击 **回到官方 App 准备**，按状态说明使用官方提词器准备流程。
4. 需要学习版式时使用公开合成稿，不用私人讲话稿当诊断样本。
5. 返回新闻页；未知通道 / 格式时不要反复传稿或复用旧会话。

### 8.2 获取与阅读

1. 点击 **订阅主题**，填写公开主题；默认 `AI`。
2. 点击 **获取新闻** / **获取新闻并发送**。
3. 点击 **查看全文与来源**，核对日期、来源链接和正文；内容由模型整理，不当作绝对事实。
4. 通道准备好时，获取成功会尝试传稿；未准备时保留手机全文。
5. 需要手动发送时点 **发送本批到眼镜**，等待收稿业务确认后自动开始。
6. 用 **开始 / 继续阅读** 或 **暂停阅读** 控制播放。
7. **滚动速度**建议从 120 开始；300、360 是实验档，出现跳字回到 240 或更低。数值单位尚未确认，不标成字/分钟。
8. 用完点击 **退出并停止**。仅关闭研究面板不会停止新闻功能。

### 8.3 自动更新与离线合成稿

- **自动更新与发送** 开启后每 **10 分钟**尝试更新；当前稿件未退出不换稿。
- 不保证系统挂起或后台仍按时刷新。
- **展开实验工具 → 合成稿测试（不联网）** 可分离验证提词通道与新闻检索。
- 重启免校准未完成；每次按当前通道状态操作。

**成功判据：** 手机有正文与来源 → 传稿有业务确认 → 镜片正文完整 → 暂停 / 继续有效 → 退出确认或实体退出明确。蓝牙写入成功不等于镜片已显示。

**依据：** [新闻页面与按钮](../NewsReader.m)、[提词通道](../NewsTeleprompter.m)、[显示状态](../NewsPresentation.m)。

## 9. 录音、转写与全天智记导出

> 仅操作自己有权处理的音频和文字，录音前取得相关人员同意。扩展“保存”开关不是官方录音 / 智记的启动开关。

### 9.1 已存在录音的文件分享

1. 在官方界面结束录音，等待本机文件落盘。
2. 进入 **资料 → 录音与文件分享**，刷新列表。
3. 选择实际存在的本机音频；按页面选择分享 / AirDrop / 存储到文件。
4. 分享创建副本，不删除原件；收件位置与权限由系统分享目标控制。
5. 官方当前录音历史全文自动导出尚未接通，不把音频文件存在当作文字全文已可读取。

### 9.2 导入或粘贴转写，整理 Markdown

1. 进入 **资料 → 转写文字整理**。
2. 导入本机 TXT / Markdown 或粘贴自己取得的转写文字。
3. 先检查内容与长度，确认允许交给自有模型。
4. 点击整理操作，等待模型输出；需要已配置可用接口。
5. 核对摘要、原意和建议行动项，再点击 **分享整理结果 Markdown**。生成文件包含输入原文，分享前检查隐私。
6. 需要中止时点 **取消本次整理**；离开此页会停止本次任务。失败、取消或截断不会被保存为完整成功结果。

**特别注意你的 HTTP 配置：** 文字整理使用独立的 HTTPS 校验与非流式 JSON 请求，当前尚未接入任意 IP HTTP 例外。因此“眼镜 HTTP 问答已成功”不代表“转写整理也可用”。当前仅配置 HTTP 的用户可先导出 / 分享原文；使用整理需要兼容的 HTTPS 模型配置，切换前记录原问答配置，不要误认为是网络坏了。导入要求非空 UTF-8 TXT / MD，最多 30 万字符 / 2 MB，逐段整理并非全文综合结论，行动项不会自动创建待办。

这一步不替换官方 ASR，不会自动上传所有录音，也不代表能一键拉取全部官方历史。

### 9.3 全天智记文字

1. 进入 **资料 → 保存之后的最终文字**，明确开启。
2. 回官方界面按官方流程启动一次短智记。
3. 停止官方智记，返回 **已保存文字** / **导出文字归档**。
4. 核对只含开启后实际收到的最终文字，再导出 Markdown。
5. 用完关闭保存；App 重启会复位扩展文字采集许可，不自动复活。

开关不能补回开启前未保存的内容，也不能承诺完整官方历史；最终文字旁路不等于音频同步保存。

### 9.4 全天智记音频

1. 进入 **资料 → 音频保存与分享**。
2. 开启 **保存之后的智记音频**，阅读真实谈话保存提示并明确同意。
3. 回官方界面启动短智记；此开关本身不会启动麦克风或智记。
4. **先停止官方智记，再关闭音频保存开关**，让文件写完。
5. 刷新、选择文件、分享副本。
6. 检查存储占用并自行管理，扩展不自动删除文件；重开 App 后重新核对开关。

只覆盖开启后官方接口实际收到的音频，实时 / 缓存可能分段，不自动拼接，不承诺无缺包。PCM 是原始格式，不能只改后缀当 WAV 播放。

**依据：** [录音文件面板](../RecordingExportsUI.m)、[转写整理](../RecordingTextUI.m)、[智记音频](../AlwaysOnAudioUI.m)、[文字归档](../Core.m)。

## 10. 知识库与 Agent

<img src="knowledge-preview.png" width="300" alt="知识库预览：只读工具、Codex、连接配置、状态、查询与最近结果" />

*图 4：未配置状态的知识库页面，不是已连接证明。*

### 10.1 先明确它能做什么

- 当前实现的是 **Codex 只读检索参考执行器**。
- 查询 Mac 已归档的项目、学习或消息资料；不会自动刷新微信，也不是读取实时数据库。
- 下拉可选择其他 Agent，但 Claude Code、Hermes、WorkBuddy、OpenClaw 等尚无本路线执行器；选择不等于连接。
- 不是任意远程命令、电脑控制、文件写入或无人值守自动操作接口。

### 10.2 操作顺序

1. 先按 [桥接服务教程](../knowledge-bridge/README.md) 在自己的电脑准备参考服务和只读资料根目录。
2. 配置独立可撤销令牌，通过受保护的 HTTPS 暴露给手机；不要将免密服务直接暴露公网。
3. 进入 **模型 → 知识库与来源 → 连接配置**，填写完整服务地址和专用令牌。
4. 选择 **Codex**，点击 **刷新连接状态**；查看真实状态，不以静态标题推断连接。
5. 先用 **发起查询** 提一个不含敏感内容的小问题，再用 **刷新最近结果** 核对状态、答案和来源。
6. 手动查询正常后，明确开启 **知识库工具**，再用兼容 Tools 的自有模型进行语音检索。
7. `knowledge_query` 返回未完成状态时按状态接口查询，不把“已受理”当作已有答案。
8. 不需要时关闭工具；更换地址需要重新输入令牌，不把旧令牌转发给新服务。

### 10.3 电脑端最小启动步骤

需要 Node.js 22.16+、已经安装并登录的 Codex。用新的本机私有目录初始化：

```sh
node official-addon/knowledge-bridge/server.mjs --init /absolute/new-private-knowledge
```

编辑该目录生成的 `config.json`：

| 配置项 | 填写原则 |
| --- | --- |
| `command` | 自己已安装的 Codex 可执行文件绝对路径；文件存在不代表登录成功 |
| `cwd` | 专用空工作目录，避免加载不可信项目配置 |
| `roots.projects` / `roots.learning` | 授权的 Markdown 副本目录 |
| `roots.wechat` | 自行归档且符合原教程格式的消息目录，不是微信实时数据库 |
| `directory` | 私有查询任务存储目录，含问题、答案、来源摘要 |
| `tokenFile` | 初始化生成的独立令牌文件，保留严格权限，不贴到聊天或日志 |

```sh
node official-addon/knowledge-bridge/server.mjs \
  --config /absolute/new-private-knowledge/config.json
```

服务默认只绑定 `127.0.0.1`。使用自己的可信 HTTPS 反向代理或 VPN TLS 服务，只转发 `/api/turbo-knowledge/`，保留 Bearer 鉴权，不暴露资料目录或整个 Codex RPC。手机连接配置示例：

```text
https://your-host.example/api/turbo-knowledge
```

这里的域名是占位符，需替换为手机可访问的真实 HTTPS 服务；手机上的 `localhost` 指手机，不是 Mac。三类来源需显式配置，空来源返回空结果，不伪造数据。单问题 2–200 字；任务未完成时按原编号查结果。服务重启会将遗留任务标为 interrupted，不自动重放。达到任务保存上限会拒绝新任务，按原教程人工管理，不随意删除未确认结果。

### 10.4 隐私与验收

命中片段可能经过 Codex 处理，结果再交给当前自有模型。把资料进入哪些服务说清楚，先用非敏感样本验证。

**成功判据分层：** 电脑服务可用 → 手机 HTTPS / 认证通过 → 手动检索有来源 → 语音模型实际调用 Tools → 镜片结果可读。项目参考实现不等于手机到 Mac 到镜片在所有环境都完整验收。

完整部署参数、环境变量和版本限制见 [可选模块参考](V2_OPTIONAL_MODULES_REFERENCE.md) 与 [桥接服务原始教程](../knowledge-bridge/README.md)。

### 11.2 第一次只做模拟验收

3. 点 **去哪里？**，填写关键词、可选城市，再点 **搜索地点**；仅输入不会逐字上传。
4. 选搜索结果，或按当前角色单击地图 / 选择地图中心，设置终点。
5. 单独设置 **模拟起点**；默认北京起点有标注，不会因搜索终点自动移动。
6. 用右侧 **＋ / －** 缩放，点 **规划路线**，核对方式、距离、时间。
7. 点 **开始模拟**；手机有新鲜指引后才点 **开启眼镜字幕显示**。
8. 等新会话 ACK，核对转向、距离、道路等文字，不期待地图图片。
9. **停止眼镜显示**只停止镜片显示，保留手机模拟；**结束导航**结束整次任务。

### 11.3 使用边界

- 普通字幕只开放模拟镜片显示，离开前台停止；**4 分钟 / 80 帧保护**、15 秒数据断流停止，不用循环重启规避。
- 手机实时导航的后台定位与镜片显示是不同通道；权限和宿主后台模式需单独配置，长期后台未完成全量验收。
- 骑行 / 驾车有实际对应 SDK 引擎，但在线路线与镜片实测不能用 mock 测试代替。
- 不提供离线地图、公交、独立电动车模式或成熟安全导航保证。
- 不边驾驶边测试，不以实验镜片结果替代道路观察。
- TNV1 的按钮是 **开启眼镜原生导航**，属于另一套构建 / 固件，见下一节。

**依据：** [导航主教程](NAVIGATION.md)、[后台权限与验收](NAVIGATION_BACKGROUND.md)、[可选模块参考](V2_OPTIONAL_MODULES_REFERENCE.md)。

## 12. 本地翻译、离线字幕与固件分支

> 本节用于识别分支和找到正确教程。**没有阅读专用构建、使用、安全和版本文件之前，不执行任何刷固件操作。**

### 12.1 iOS 26+ 本地翻译 / 英语离线字幕（无需刷固件）

- 独立入口，**不是普通问答 ASR 的替换**。
- Apple / Hy-MT2 本地文字翻译、Parakeet 英语识别；需自行准备语言包和模型。
- 显式 `TIO_LOCAL_TRANSLATION=1` 编译，使用对应输出与打包方式；不是只填 Key 开通。
- 先在手机验证模型与授权，再验证原文 / 预译 / 修正与镜片同步；前台采集有 20 分钟保护。
- 不是眼镜前方 / 四周定向收音，不承诺所有官方翻译业务被替换。
- 当前任意 IP HTTP 普通分支禁止与本地翻译实验混编，不组合宏强行构建。

#### 在手机上按步骤使用

1. 按 [本地翻译 README](../local-translation/README.md) 的固定提交与模型许可步骤，在 Apple Silicon Mac 上准备依赖，不替换文件名绕过哈希校验。
2. 使用原教程的 `build.py --llama … --fluid … --out …` 构建独立翻译模块，再构建 `TIO_LOCAL_TRANSLATION=1` 的宿主入口。
3. 签名打包时成对添加 `--translation-module-dir` 与 `--translation-models`；只加宿主 dylib 不够。
4. 进入 **资料 → Apple / Hy-MT2 本地翻译**，先测试短句。Apple 引擎先点 **准备 Apple 语言包** 并同意系统下载；Hy-MT2 校验随包模型。
5. 点击右上角麦克风进入 **英语离线字幕**，选择仅英文 / 翻译引擎、输入设备、是否同步眼镜。
6. 停止音乐、TTS、问答、录音和导航，主动点开始并允许麦克风，等待首次模型加载。
7. 说英语，核对先出现英文、再出现带“预译”标识的译文；希望更稳定可关快速预译。
8. 同步眼镜需等待本次 SID 成功回执并实际看镜片。失败先关闭同步，只测手机收音，不强抢官方会话。
9. 停止或退出页面会取消收音 / 翻译。退后台、中断或输入路由变化也会停止。

完整下载、编译和签名命令以 [本地翻译 README](../local-translation/README.md) 为准；该路线当前文档使用 iOS 27 SDK / Swift 6.4，目标最低 iOS 26，不保证本机旧 SDK 能直接构建。

#### 已有匹配 TMU1 的音乐日常步骤（不含刷写）

1. 确认专用手机扩展与精确固件均已完成各自验收，升级或传输没有处于进行中。
2. 进入 **TurboIO → 资料与导出 → 网易云音乐**，先从右上角菜单播放本机校验曲。
3. 核对音频路由，再搜索并选择服务实际允许播放的歌曲；不能绕过会员、区域、版权或试听限制。
4. 开启眼镜同步、选择显示时长，检查封面、五行歌词、手机拖动进度与暂停 / 继续。
5. 先用手机切歌，避免误触旋钮；已知灵敏问题不属于配置错误。
6. 用对应页面停止 / 退出，再恢复其他语音或显示任务。扫码登录未完成验收，不用非正规方式绕过环境限制。

#### 已有匹配阅读集成的使用顺序

1. 普通 V2 不自带 TWR1 可用菜单；先确认自己确实装的是匹配阅读模块或 FOCUS 集成版。
2. 在该分支的阅读 / 书架入口准备自己有权使用的 TXT / EPUB 或已授权书架数据。
3. 先用合成短文验证分页、返回、断连与缓冲回收，再测试真实资料。
4. 书架 Key / 统计结果不代表能获得章节正文，公开版不提供网页取文或 Cookie。
5. 长按旋钮返回存在分支已知问题；异常时停止，不继续刷不同候选尝试“修复”。

#### FOCUS 番茄时钟

1. 完成 FOCUS-04 配套验收后，进入 **Turbo IO → 首页 → 番茄时钟**。
2. 选择 **眼镜独立计时**，刷新确认回执，选 15 / 25 / 45 分钟；更多设置支持 5–120 分钟和 30 秒验收。
3. 手机开始 / 暂停 / 继续 / 结束；眼镜短按暂停 / 继续，长按停止并退出。
4. 前 3 秒完整显示，之后小提示，约 10 秒释放亮屏保持；不是常亮，到时空闲才提醒，重启眼镜会中断本轮。
5. **手机本机** 模式只本地计时，切后台返回不重置，但没有手机后台提醒，也不发眼镜命令，不能与眼镜独立模式混为一谈。

### 12.3 Android 不套用 iOS 教程

Android 路线见 [android-addon/README.md](../../android-addon/README.md) 与 [逐步安装 / 刷写教程](../../android-addon/docs/INSTALL_AND_FLASH.md)。依赖、构建输出、宿主兼容和安装方式独立；本手册的 IPA、Mach-O、dylib、Apple 签名、Sideloadly 不适用。不要把 iOS 功能验收外推为 Android 已实现。

1. 从 Android README 指定 Release 核对 APK 与摘要；公开 APK 已含扩展，不必再合并 iOS 插件。
2. 先备份旧 App 数据。签名与官方不同，不能保证覆盖安装；遇冲突不承诺无损迁移。
3. 按 Android 专用教程安装、登录、连接，并检查对应菜单和自己配置的模型 / 服务。
4. 先验收 APK 与官方连接，不将安装成功视为音乐、阅读、导航或固件已匹配。
5. GUARD-07 / TAP1 是独立高风险分支，不是 APK 安装必做项。升级后需按专用教程完成自然返回首页、只读回查、显示 TEST 与 `LOCKED / 授权0 / 结果保护未开始` 核对，再进行日常功能测试；状态不明不释放保护。
6. 源码构建需 JDK、Android SDK platform 36 / build-tools 36.0.0、apktool 等，产物仍需自己的 `zipalign` / `apksigner` 签名；保持同一签名密钥才可能覆盖自己旧版本。

公开 Android 移除了微信读书网页正文适配及专属字幕地址；不要照私用演示期待这些入口。详细源码命令和精确输入摘要在 Android README / 参考附录，不复用历史 1.0.4 的流程。

## 13. 诊断与常见问题

先做分层排查：

```text
安装 / 签名 → App 启动 → 官方登录与连接 → 扩展适配
    → 模型 / 服务 → 本轮接管 → 镜片显示 → 音频 → 退出
```

| 现象 | 先检查 / 操作 | 不要做 |
| --- | --- | --- |
| `node: command not found` | 激活 Node 22.16+，核对本次终端 PATH | 为环境问题改业务源码 |
| 版本 / UUID 不匹配 | 核对原厂版本、Build、UUID，换正确合法输入 | 篡改版本号、去掉门禁 |
| 动态库已嵌入 | 从未修改原始副本重新合并；预合并包关闭额外注入 | 在已有扩展的包上重复合并 |
| 安装 `ApplicationVerificationFailed / 0xe8008001` | 验签、描述文件、目标与归档资源；本机旧包有 AppleDouble 缺失资源问题，重建修正版 | 归咎于模型 Key；直接卸载唯一副本 |
| 找不到 TurboIO | 官方主页四项齐全、前台无键盘 / 弹层、备用研究入口、VoiceOver 与诊断状态 | 反复解绑、刷固件 |
| 底栏仍亮白 | 是否已安装本轮固定深色库；HTTP 用户是否构建了正确目标 | 认为改源码会自动更新手机 |
| HTTP 地址不能保存 / 请求 | 是否已安装任意 IP 研究新包、数字 IP / 端口 / 路径是否规范、是否重新填 Key | 用旧固定 IP 包期待放开；填写 HTTP 域名或绕过校验 |
| 局域网模型测试失败 | 手机接入正确 Wi-Fi、Windows 服务监听可达、局域网权限、对应端口防火墙、Key、模型 ID | 笼统关闭整个防火墙；手机填电脑的 `localhost` |
| API 成功但仍官方回答 | 本轮模式是否自定义；重启复位；普通聊天业务与合格回包、服务实际请求 | 把接口弹窗当镜片验收 |
| 文字有、声音无 | 同步朗读开关、引擎、测试语音、音频路由、系统音量、云 Key | 先重签 / 解绑 |
| 搜索无实际请求 | 搜索开关、Key、模型 Tools 支持；查看实际次数 | 认为开关打开就必搜 |
| 待办说成功但没新增 | 查看官方列表新条目 / 新 ID；结果不明先人工确认 | 超时后重复创建，造成重项 |
| 新闻无法传稿 | 提词通道准备、当前稿件退出、收稿确认、合成稿测试 | 把蓝牙写入当显示成功；多个任务抢同一通道 |
| 导出没有历史全文 / 音频 | 是否开启保存后实际收到；本机文件是否落盘；官方任务和保存开关是否停止 | 承诺恢复未保存历史 |
| 知识库无法连接 | HTTPS、独立令牌、Mac 服务、只读根目录、Codex 状态 | 选择未实现 Agent 后声称已接通 |
| 地图无结果 | SDK 构建、资源参数、iOS Key / 服务权限、显式搜索 | 只填 Key 或复用 Web 服务 Key |
| 字幕约 4 分钟停 | 普通导航保护、前台、数据断流 | 循环自动重启绕保护 |
| 续签失败 / 配置丢失 | 同账号、同标识、新 IPA 缓存、额外注入、电脑后台状态 | 用删除 App 代替更新或续签 |

**本机打包的 AppleDouble 问题：** 旧归档方式可能添加 `._*` / `__MACOSX`，签名器封存后被解包器丢弃，导致资源校验失败。HTTP 预合并器已采用 `ditto --norsrc --noextattr --noacl` 并检查归档条目；按当前工具重新生成，不继续使用旧故障包。详见 [安装故障记录](LOCAL_HTTP_RESEARCH.md)。

报告问题仅提供：App / Build、构建路线、系统 / 固件版本、最短复现步骤、脱敏错误码。**不提交 IPA、私钥、描述文件、设备标识、Key、完整沙盒、私人录音或聊天日志。**

## 14. 验收与隐私清单

### 14.1 每次新包的最小验收

- [ ] 使用正确原厂输入和扩展目标，没有重复注入。
- [ ] App 能打开，原有官方登录和眼镜连接正常。
- [ ] 前四项官方导航有效，TurboIO 可进入，关闭返回同一宿主。
- [ ] 若为本轮普通版本，系统浅色下底栏仍深色；长按回退有效。
- [ ] 合成模型测试成功，服务日志显示预期模型请求。
- [ ] 普通眼镜问答镜片正文完整，不混入另一轮输出。
- [ ] 所选 TTS 实际听到完整回答，能明确退出。
- [ ] 录音 / 智记 / 新闻等任务结束，采集与自动更新许可按需关闭。
- [ ] 需续签时缓存为新包、同账号 / 标识，更新后配置再核对。

### 14.2 数据去了哪里

| 操作 | 可能流向 |
| --- | --- |
| 普通 V2 语音识别 | 官方 ASR / 服务，不能声称完全离线 |
| 自有模型问答 | 识别文字、个人资料提示词、有限上下文 → 自有模型 |
| TinyFish | 检索词 → 搜索服务；摘要 → 自有模型 |
| 云端 TTS | 回答文字 → 云朗读服务 |
| 知识库 | 问题 / 命中片段 → 自建服务与 Codex，结果 → 当前模型 |
| 转写整理 | 用户确认的导入 / 粘贴正文 → 自有模型 |
| 音频分享 | 本机副本 → 用户选择的系统分享目标 |
| 高德 | 用户同意后的地图 / 搜索 / 定位数据 → SDK 服务 |
| HTTP 专用模型 | Key 与正文以明文通过局域网 / 公网，认证不等于加密；新研究包 ATS 为整个 App 范围放宽 |

Key 存钥匙串不代表服务端没有日志；清空扩展上下文不清除官方或供应商记录。只读执行器也可能处理敏感正文，先确定自己有权限和接受服务处理范围。

### 14.3 尚未承诺的能力

不将下列能力当作已完成：任意眼镜 UI / 像素截图、完整官方历史导出、知识库全环境手机到 Mac 到镜片闭环、APNs 主动推送、其他 Agent 通用执行器、待办全功能双向同步、所有固件兼容、新闻重启免校准、全部长期后台稳定性、无人值守续签到期前刷新、最新固定深色底栏精确视觉一致。
