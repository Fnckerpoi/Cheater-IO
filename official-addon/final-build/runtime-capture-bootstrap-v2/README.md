## Actual lifecycle

1. A real OwnFlutter dylib has an ordinary linker-generated __DATA,__la_symbol_ptr (not mmap). File symbol/indirect metadata identifies its unique _dlsym slot. OwnEngine is another real dylib, with a unique defined isar_open_instance whose VA and UUID are parsed from its actual file.
2. The adapter constructor validates the exact self image paths/UUIDs, verifies no OwnFlutter lookup has occurred, checks actual current-task VM slot mapping RW/non-executable/aligned, and asks task90 to authenticate the actual resolved import pointer. A raw helper address is **not** accepted as a wildcard. It binds task71's real resolver and performs one CAS on the self slot. No target lookup is manufactured by the constructor.
3. The assembly selector sends non-DEFAULT handles through task71's unchanged transparent tail bridge. DEFAULT safely checks the bounded literal name, calls the real imported resolver once, and only considers a result exactly equal to self-engine slide+derived exportVA. Its first successful hidden task93 bind stores the original for process lifetime.
4. After that qualified lookup, still before returning the typed wrapper, the adapter derives a directory from the actual main Runner. It requires the exact generated Runner path and UUID, opens the absolute containing path one component at a time using dirfd/O_DIRECTORY/O_NOFOLLOW/CLOEXEC, reads the exact fixed public fixture Info.plist bytes and compares them to generated policy, then opens/creates fixed Documents and ManuscriptLab descendants. The dedicated ManuscriptLab directory must be current-euid/exact0700. No caller home/path/fd/proof parameter is accepted by the adapter interface.
5. Only then does it pass the descriptor to task97 TIOCaptureStartInternal, close its own descriptor and let the core retain its separately verified descriptor. Bind alone is WAITING; Start succeeds with no file. The first real nonnull-key open becomes KeyRejected, with no copy/file. The following null-key schema open becomes Written only after strict schema projection, actual atomic0600 file publication, and owned cleanup. The original consumes/frees its schema object/payload and returns exactly once on each call.

The filesystem traversal and Start occur on the qualified real DEFAULT lookup path in the self fixture, **not inside the constructor**. This does not claim that filesystem traversal or collection is safe under every possible real lookup context. The fixture Runner calls after main has begun; the adapter's own directory identity is synthetic self policy, not an approved device Lab container. A production design still needs reviewed actual bundle/container qualification and timing/context authority.
