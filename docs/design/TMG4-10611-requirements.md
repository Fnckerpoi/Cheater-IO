# TMG4-10611 开发需求确认稿

状态：待用户确认  
需求基线：Strix OS `1.0.6.11`  
自定义固件代号：`TMG4-10611`

## 1. 开发目标

沿用项目现有 OTA 通道和官方升级流程，以 `1.0.6.11` 为基座构建精简固件 `TMG4-10611`。从 APP 与固件 AP 中移除自定义导航、番茄闹钟、微信读书、网易云音乐四项功能，保留其他功能及其必要的共享能力。

本文件用于确认开发范围和验收标准，不代表源码修改、构建或设备验收已经完成。

## 3. 功能删除要求

| 功能 | APP 侧 | AP 侧 |
| --- | --- | --- |
| 自定义导航 | 移除功能入口、路线规划、模拟导航、导航会话、专属配置与后台任务 | 移除自定义导航入口、界面、导航会话及专属消息与文件处理 |
| 番茄闹钟／番茄时钟 | 移除入口、计时控制、状态展示、专属通知和后台任务 | 移除计时功能、专属界面、消息与文件处理 |
| 微信读书 | 移除入口、书架同步、正文导入、封面处理、阅读设置及阅读会话 | 移除书架与阅读界面、翻页与滚动业务及专属传输处理 |
| 网易云音乐 | 移除入口、账号设置、搜索播放、播放器和音乐同步 | 移除音乐界面、歌词与播放控制及专属传输处理 |

删除要求覆盖初始化、事件订阅、退出清理、显示互斥、定时任务、资源打包、构建引用和相关文案。仅隐藏入口不满足本需求；不得用空实现保留被删除的业务模块。

APP 首页调整为只显示保留功能，去除空卡片和失效入口。说明文字、诊断信息与设置页不得继续将四个功能描述为可用能力。

## 4. 共享能力保留要求

以下代码存在跨功能依赖，必须先分离共享职责，再删除业务实现：

| 共享能力 | 当前依赖证据 | TMG4 要求 |
| --- | --- | --- |
| 眼镜字幕显示与会话清理 | 云端字幕、SCADA 字幕调用 `NavGlasses` | 保留显示、所有权与清理能力，移除路线导航业务 |
| 通用整数读取与 CRC | `AppCodec` 调用 `FocusCodec.u32`、`FocusCodec.crc` | 将必要通用逻辑与番茄业务分开，保留应用包兼容性 |
| UTF-8 解码 | `BoundedWebSocket` 调用 `ReaderCodec.utf8` | 保留原有解码行为，解除对阅读业务类的依赖 |
| 固件菜单与绘制 | 菜单主实现位于音乐目录，菜单绘制位于番茄目录 | 保留所需菜单能力，更新项目顺序、数量和点击映射 |
| 固件公共状态与输入 | 应用运行时、情境英语等使用导航目录中的显示接口及阅读目录中的输入辅助 | 保留必要接口与输入语义，解除对四个业务服务的依赖 |

保留功能包括现有模型与对话、Agent-Anywhere、字幕与翻译、新闻、SCADA、仪表盘、应用广场，以及 AP 上现有情境英语、Dots、显示测试、遥控拍照、滴滴等功能。共享重构不得改变保留功能的协议和实际操作语义。

## 5. 版本身份与现有升级流程

### 5.1 身份定义

- `1.0.6.11` 表示官方基座，`TMG4-10611` 表示本项目的自定义固件构建身份，两者分别记录。
- APP 显示、候选包信息、准备目录核对、操作提示及结果记录应一致识别 TMG4。
- 新包的大小、清单和摘要以实际构建产物为准，不能沿用 TMG3 的包身份数据或只修改文件名。
- 历史待确认升级结果保留原身份，升级 APP 不得将其自动转换成 TMG4 或自动解除保护。
- 官方查询版本码、设备回读版本和自定义代号是不同字段。查询与回读字段以对应基座的实际证据确定，不从 `TMG4-10611` 字符串推导数值。

### 5.2 现有流程保持

继续使用现有官方更新页、下载器、校验、解压和传输流程。准备模式继续只执行下载与核对；正式升级继续沿用现有独立授权及结果确认流程。

与本需求相关的调整位置：

| --- | --- |
| [OtaProfile.java](../../android-addon/src/com/turboio/addon/OtaProfile.java) | 登记 TMG4 的基座、代号和实际包身份，保留历史结果识别 |
| [OfficialOtaPreparation.java](../../android-addon/src/com/turboio/addon/OfficialOtaPreparation.java) | 对应新候选身份，准备目录与成员数量和实际新包一致 |

## 6. 开发交付物

1. 精简后的 APP 源码与相应构建配置。
2. 基于指定官方基座的 TMG4 AP 源码、构建入口与候选固件包。
3. 与新产物一致的版本档案、清单及包核对数据。
4. 模块移除和保留功能的针对性测试结果。
5. 构建说明、变更说明及分阶段设备验收记录。

候选固件继续沿用现有 AP 自定义方式；其余官方载荷及烧录元数据保持指定基座内容。

## 7. 验收标准

| 编号 | 验收内容 | 通过标准 |
| --- | --- | --- |
| A1 | APP 功能精简 | 四个自定义功能没有入口、初始化、后台任务或仍可触发的业务处理 |
| A2 | APP 构建 | 不依赖被移除的业务类；必要共享逻辑仍可编译并通过针对性测试 |
| A3 | APP 保留功能 | 对话、字幕、SCADA、仪表盘、应用广场及其他保留功能不因精简失效 |
| F1 | AP 功能精简 | 四个自定义功能不进入新构建；对应菜单、文件和消息入口均已清理 |
| F2 | AP 菜单 | 数量、排列、选中、点击和退出一致，原厂项与保留自定义项无错位 |
| F3 | AP 保留功能 | 情境英语、Dots、显示、遥控拍照、滴滴、应用运行时等完成针对性回归 |
| V1 | 版本绑定 | 各处一致使用指定基座与 `TMG4-10611`，包数据匹配实际产物 |
| O1 | 升级准备 | 沿原流程完成检测、下载、解压及目录核对，准备模式不开始刷写 |
| O2 | 升级结果 | 分别记录设备安装、自然重启、版本回读及功能实测，传输完成不等同于安装成功 |
| H1 | 历史结果 | 历史待确认记录维持对应身份，不被新版本自动解除 |

离线测试和设备验收分别记录。保留原厂功能时，不以原厂包中仍存在导航字样判定自定义导航删除失败。
