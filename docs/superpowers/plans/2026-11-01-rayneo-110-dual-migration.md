# 雷鸟 APP 1.0.10 与 Strix OS 双端迁移实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpower-subagent-driven-development or superpower-executing-plans. Execute only after plan review. Steps use checkboxes.

**Goal:** 迁移现有 Turbo-IO 手机和眼镜功能，分别构建基于真实目标版本的候选并完成分层验收。

**Architecture:** 安卓及眼镜固件分别审计版本专属接口，再对照既有功能整合；协议、显示和 OTA 通道以匹配的双端证据验收。未知固件 ABI 不沿用旧地址。

**Tech Stack:** Android Java/D8、APKTool、Python、Cortex-M33 LLVM、C、项目既有静态审计与测试工具。

**Spec:** artifacts/rayneo-110-migration/双端迁移规格草案.md

## 全局约束

- 手机输入为官方 APP 1.0.10、versionCode 258，保留四个官方 DEX；扩展 DEX 使用无冲突位置。
- 功能来源包括 e3101fd 工作台分支和既有已交付功能；先比较完整差异，不能把旧任务的测试结果视为新版验收。
- 固件须取得与目标型号和版本匹配的原厂完整 OTA 与清单；重定位原厂符号、对象布局、调用约定和补丁位置，禁止使用旧版地址推定新版地址。
- 编译和校验工具必须实际可用；缺失输入时只停止依赖该输入的工作，不跳过门禁。
- 固件刷写需根据具体候选另行确认；眼镜光学与交互效果由用户验收。

## 审查重点

- 新版 DEX 槽冲突或原厂类被覆盖：打包测试逐成员验证四个原厂 DEX 的预期变化，扩展 DEX 单独存在。
- 混淆符号与语义变化：逐个比对声明、调用者与行为，缺失或歧义时不注册批准适配器。
- 版本或 OTA 载荷错配：清单、设备型号及版本和实际原厂包须一致，负例必须拒绝。
- 签名与账户数据：确认候选签名和安装策略后才安排设备安装；不能推断覆盖安装成功或数据保留。
- 主页卡片回执不符或重连后停发：针对真实协议与生命周期建立复现和验证，禁止以离线模型测试代替眼镜实测。

## 阶段 A：安卓宿主与功能基线

**范围：** android-addon/、既有工作台隔离分支、artifacts/rayneo-110-migration/。

- [ ] 使用 host-audit.json 和 host-audit.md 的 1.0.7 对照结果定位新版 ASR/NLP/完成回调、SDK 插件事件、传输对象、manager、OTA 队列和反射依赖；逐项记录新签名、调用者和证据。
- [ ] 比较 e3101fd 与其他功能分支，明确 AA、语音、字幕、看板、工作台和 OTA 代码的来源与冲突；记录可构建的整合基线。
- [ ] 对新版 Manifest、原生 libapp.so、嵌入 payload 和 OTA 来源约束单独审计，记录未检查项；未知符号不得登记为已支持。
- [ ] 产出可供实现的新版符号映射及测试清单，包含缺失、歧义、签名改变和原生来源不匹配的拒绝用例。静态结果与设备运行证据分开记录。

## 阶段 B：安卓适配与构建

**范围：** android-addon/profiles/、host-build.mjs、宿主符号映射、打包脚本及对应测试；涉及文件以阶段 A 实测映射确定。

- [ ] 从隔离工作树出发，为 1.0.10 的完整版本契约编写失败测试：未知 APK、缺失回调、错误包、重复 DEX 和原厂 DEX 被覆盖均拒绝。
- [ ] 实现新版专属宿主适配、事件挂接与打包路径；保留官方 DEX，新增扩展 DEX，整合已审阅功能和 AA payload。不得放宽旧版本的准入和 OTA 约束。
- [ ] 针对映射、桥接、清单、打包和功能运行相关测试，并运行完整适用回归；验证失败先修复再继续。
- [ ] 用真实官方 APK、payload 与 sidecar 构建候选，核对 ZIP 成员、原厂载荷、签名策略与报告；设备安装前确认签名和数据迁移方式。

## 阶段 C：固件基线与 ABI

**范围：** firmware-research/，目标 OTA 的独立审计目录。

- [ ] 核对眼镜型号、设备实读版本、目标版本及对应官方完整 OTA；检查清单、各负载及来源。当前仅发现旧版原厂归档，不能推定其为目标包。
- [ ] 定位并验证 Python 和 Cortex-M33 的 clang、ld.lld、llvm-nm、llvm-objcopy；记录版本和可执行路径。缺失时停止依赖工具链的编译。
- [ ] 基于目标原厂 AP，逐项分析旧扩展依赖的原生调用、对象布局、资源、启动描述符、补丁位置和空间；形成有来源的符号映射及协议契约。
- [ ] 对卡片解析、显示生命周期、回执和断连重连建立可重现验证；区分纯核心复用与设备 ABI 适配。目标原包或关键 ABI 不明时不生成固件候选。

## 阶段 D：固件迁移及双端验收

- [ ] 在隔离目录迁移地址无关核心和已经逐项确认的目标绑定；编写可运行的正反例，覆盖错误版本、载荷错配、对象布局、并发生命周期和协议边界。
- [ ] 使用匹配工具链运行固件编译、静态审计、原厂其他载荷及清单比较和可用 ARM 仿真；失败不得发布候选。
- [ ] 配对手机与固件候选，完成协议离线回放、手机安装条件核查、只下载验证和设备可做的非刷写检查；记录每项的证据和未验证项。
- [ ] 整理具体固件候选、设备状态和风险供用户决定是否刷写；刷写获另行确认后再执行。用户佩戴眼镜验收主页共存、字幕、看板和交互。

## 依赖关系

A 和 C 的调查可并行；B 依赖 A 的符号证据；D 依赖 B、C 的真实输入、工具和适配结果。每个实现任务在确定目标版本接口后拆分为包含精确文件、接口和可执行正反例的工作项，再执行、独立审查与集成。
