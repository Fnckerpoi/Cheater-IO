1. 项目简介

Turbo IO 围绕 RayNeo iO 眼镜提供手机侧扩展、独立客户端研究、应用与仪表盘工具链，以及特定版本的固件研究。它不是官方 SDK，也不是适配所有版本的统一刷机工具。

三层开发对象

层次 你可以开发什么 先读
手机侧 模型、字幕、音乐、导航、阅读，以及蓝牙业务桥接 Android 专题、其他平台
Server / 应用 SDK 将自有数据变成卡片、原生小应用 ZIP 应用入门、服务端
眼镜 AP 在固定底座上研究菜单、协议与原生运行时 固件边界

手机模型接入和部分字幕可以复用原厂显示；新增原生菜单、图形仪表盘与小应用需要相应实验运行时。安装 APK 不等于安装眼镜固件。已有兼容运行时后，导入兼容应用不要求每次重刷。

V1 与 V2

V1 指 iOS 独立客户端与分层 Swift SDK 的研究路线；V2 指复用官方宿主配对、通信与业务链路的手机扩展路线。这里的 V1/V2 不是厂商 App 版本号，也不是 Strix 固件版本号。Android 当前路线是宿主扩展，不是独立 Android BLE SDK。

如何阅读证据

源码存在、单测通过、本机成功构建、模拟器表现、蓝牙回执、镜片效果、特定设备用户反馈是不同层次。历史说明可能只描述某一层、某个构建或某台设备；本手册按兼容矩阵记录范围，不把历史成功推广到新组合。

6. 全项目架构

Turbo IO 有多条产品与研究路线。应用 SDK 的自托管链路、V2 手机宿主扩展和 V1 独立客户端共享部分协议认识，但各自构建与验收。

应用与卡片的数据流

数据源不是眼镜应用的运行环境。当前链路如下：

text
自有 Server / 授权 MCP
  → 白名单展示字段
  → Python SDK：卡片文档或版本化应用 ZIP
  → 校验、哈希、SVG 预览
  → 手机预览和人工确认
  → 现有蓝牙业务桥
  → 兼容 TCE1 / TAP1 / TAX1 原生运行时

MCP 在 Server 上运行，JS 在开发机参与构建；眼镜不运行 MCP、浏览器、任意 HTML 或 JS。ZIP 是有界页面和资源，不是远程脚本执行包。应用包安装与 Dashboard API 的发布/批准任务是两条入口，不能将卡片 API 发布称为自动应用安装。

V2：复用宿主

Android 扩展和 iOS 插件沿用官方宿主的配对与通信，增加 UI、数据转换与特定消息桥接。Android 基于 1.0.5（201），iOS TMIG1 基于 1.0.6（218）；官方更新可能改变类、符号、ABI、文件、校验或生命周期。详细看 Android 调用链 与 平台路线。

V1：独立客户端与分层 SDK

独立 iOS App 管连接、音频、会话与归档，复用厂商通信核心并逐步抽出纯 Swift 逻辑。语音链路里，ASR 句末、模型流结束、提交显示和 TTS 完成是不同事件；取消与代际隔离必须防止旧回调污染新会话。SDK 接受发送也不是镜片渲染完成的证据。

固件层与边界

手机模型和部分字幕能力可复用原厂业务；图形仪表盘、原生菜单及小应用依赖配套 AP 运行时。AP 内容修改范围与 OTA 实际安装范围不同，版本迁移需重新核对 ABI 和全部候选校验，见固件说明。

状态不能合并

信号 可以证明 不能证明

SVG 预览 开发机重绘可读 眼镜字体、裁剪、亮度一致
API 发布成功 快照进入批准流程 手机在线、已显示

7. 第一个应用与仪表盘

先生成一个不联网的城市天气应用。样例来自仓库现有 gallery CLI，不需要模型 Key、MCP 服务、手机或刷机。演示天气不是实时查询。

1. 安装并生成 ZIP

从仓库根开始：

sh
cd dashboard-service
uv sync --locked

创建新的输出目录。POSIX Shell：

sh
mkdir -p .state/docs-demo

Windows PowerShell：

powershell
New-Item -ItemType Directory -Force .state/docs-demo

然后两种终端都可运行：

sh
uv run turbo-app gallery list
uv run turbo-app gallery build city_weather --out .state/docs-demo/weather.zip
uv run turbo-app check .state/docs-demo/weather.zip
uv run turbo-app preview .state/docs-demo/weather.zip --page home --out .state/docs-demo/weather.svg

输出 ZIP、校验结果与 SVG；用浏览器打开 SVG 阅读布局。输出文件已存在时工具拒绝覆盖，重复练习请换目录或文件名。预览使用电脑字体，不是镜片截图。

2. 用自己的数据更新

Server 只提取需要显示的字段，在 dashboard-service/snapshot.json 创建自己的快照：

json
{
  "headline": "我的天气快照",
  "lines": ["当前数据尚未接入", "请替换为授权查询结果"],
  "observedAt": "2026-10-15T09:00:00+08:00"
}

时间只是格式示例，必须换成数据实际采集时间。只允许这三个字段；lines 1–4 条，每个字符串最多 80 UTF-8 字节，不允许控制字符，时间需要时区。中文字符的字节数不是字符数。

sh
uv run turbo-app gallery build city_weather --data snapshot.json --version 2 --out .state/docs-demo/weather-v2.zip
uv run turbo-app check .state/docs-demo/weather-v2.zip
uv run turbo-app preview .state/docs-demo/weather-v2.zip --page home --out .state/docs-demo/weather-v2.svg

同一应用 ID 的更新提高 version。不要把 Token、Cookie、完整 MCP 响应或网页放入快照；后端接入见服务端指南。

8. 服务端与 MCP 接入

dashboard-service 是用户自托管的 Python API、SDK 和 MCP 适配层，不依赖维护者的账号或服务。先本机运行，再决定远程访问方式。

本机启动

从仓库根进入 dashboard-service，运行 uv sync --locked 并创建 .state 目录（PowerShell 使用 New-Item -ItemType Directory -Force .state，POSIX 使用 mkdir -p .state）。

sh
uv run turbo-dashboard grant --role writer --device my_glasses --out .state/writer.token
uv run turbo-dashboard serve

默认地址 http://127.0.0.1:18796，不自动部署公网、不连接设备。Token 写入新文件，不打印内容；文件存在拒绝覆盖，数据库只存哈希。GET /health 无需认证，其他接口及 OpenAPI 要求 Bearer Token。

另一个终端在同目录运行现有样例。POSIX Shell：

sh
TURBOIO_TOKEN_FILE="$PWD/.state/writer.token" uv run python examples/backend_metrics.py

PowerShell：

powershell
$env:TURBOIO_TOKEN_FILE = "$PWD/.state/writer.token"
uv run python examples/backend_metrics.py

样例写入 CPU 演示数据草稿，不读取真实账户，也不自动发布。

卡片发布状态

text
草稿 revision → 校验 / 预览 → 不可变发布快照
→ awaiting_phone_approval → 手机核对 exact hash 并批准
→ sending → 手机回执 / 结果未知

更新草稿需 expectedRevision；发布含 revision、hash、idempotencyKey、ttlSeconds。重复幂等键与不同内容、旧 revision 覆盖都会被拒绝。超时的 outcome_unknown 需要手机核对并完成回执，不自动重发。

Token 角色 使用者 职责
reader 查询端 / Agent 读取其设备范围内数据
writer Server / Agent 创建和更新草稿、发布快照
phone 手机 核对身份、批准 exact hash、提交回执

不要向模型提供 phone Token。当前 Token 长效，没有完整用户体系、撤销命令或轮换界面，仅适合单所有者本机预览；远程使用由所有者配置 HTTPS、访问控制与凭据管理。手机连接测试版要求 HTTPS，设备绑定和固件 TCE1 也必须匹配。

MCP 的两种关系

一是本项目 turbo-dashboard-mcp 暴露卡片 API 工具；二是你的 Server 连接第三方 MCP 获取授权数据，再交给应用 SDK。二者都不在眼镜运行。

第三方工具先实际 tools/list，核对名称、参数、许可和权限，只选需要的只读数据。将结果投影为 headline、lines、observedAt；缺字段显示“暂无数据”，记录来源时间，不把缓存说成实时。完整响应和工具描述不进入 ZIP。

12. Android 运行架构与耦合边界

扩展复用官方宿主的生命周期、语音和传输能力；Java 反射减少编译时厂商依赖，却保留了对运行时类名、签名、字段、枚举及协议的精确依赖。反射回退不是跨版本兼容层。

打包检查和运行时检查分工

profileFor 首先按整个 APK SHA-256 选择 profile；未知输入直接失败。当前打包器随后仅允许 1.0.5。 verifyHost 检查精确 DEX descriptor 和逐行方法/字段声明，包含语音 listener、MainActivity、事件桥、传输管理器、消息构造器、高德接口及 OTA 队列。定位类时校验 .class descriptor，兼顾大小写不敏感文件系统的 apktool 命名差异，要求恰好一个匹配。

这是已有的自动化 fail-closed 防线，不是“靠人工改混淆名”。它无法覆盖所有运行时约定：NlpResult 的 getter/setter、线程顺序、字段语义、服务行为等还需源码/设备验证。ABI 检查通过不保证未知版本可运行。

四个方法如何包装

wrap 将原方法重命名为 turboioOriginal_方法名，追加同签名入口。重复执行时保留原方法体、替换已生成入口。其 returnMode 参数目前没有用于选择分支；不能根据调用处 after/guard 字样判断执行顺序。

入口 生成的 smali 行为 Java 桥实际行为
onAsrResult 先 dispatchAsr；桥直接抛 Throwable 时调用原方法 serial 到主线程，先反射原 ASR，再观察语音和 onAsr；原 ASR 分发失败则返回
onNlpResult 先 dispatchNlp；桥直接抛出时回退原方法 onNlp 返回 false 才转发官方结果；扩展已接管则消费
onResponseComplete 先 dispatchComplete；桥直接抛出时回退原方法 onComplete 返回 false 才转发官方完成并结束朗读
onPostResume 先原生命周期，再 install 安装原生入口、初始化各模块；安装异常被包装器吞掉

桥将工作投递主线程后发生的错误不属于 smali 同步 catch 的覆盖范围。Java 内部也有自己的异常处理和诊断，不能理解成任意错误都能恢复原业务。

invokeTyped 优先查找 turboioOriginal_*，不存在时查原方法名；调用期间设置线程局部 BYPASS 防止重入。它解决包装/未包装方法路径选择，仍要求精确参数和返回对象契约，不能证明支持其他宿主。

通道、文件与确认

HostBusiness.java 严格映射已审查整数及精确名称：9/MARS_FOTA、15/LAUNCHER、19/AI_SUBTITLE、20/TELEPROMPTER；不使用 enum ordinal 或模糊子串。 NativeTransfer 通过 E3.u.h、E3.Q、P3.h、E3.b 等宿主运行时对象发消息或文件，连接由官方宿主维持。

文件事件与镜片业务 ACK 是两种证据。TransferGate 关联设备、原生任务、请求号、会话和时限；文件发送成功不等于镜片接受执行。不确定结果进入隔离等待，避免盲重发。各控制器还要验证自己的协议响应；番茄时钟、阅读、音乐、导航、卡片等需要相应眼镜运行时。

事件桥 z 也不是简单“总先原后扩展”：先执行 OTA EVENT_GUARD；需要消费/保护时可提前返回。允许通过的事件才进入原 z，随后由 NativeTransfer 观察有限元数据/复制载荷，不共享厂商可变 Map。

OTA 为什么额外耦合

受保护官方路径包括两层，不能只移植 Java 方法：

  1. Java/SDK 层：包装 E3.V.o(E3.Q) 队列、E3.u.v(...) 文件发送和事件入口。OfficialOtaBridge → preparation → legacy 控制器依次做适用策略选择；拒绝/异常时阻止发送。字段、枚举 MARS_FOTA、消息结构、官方目录与回执都依赖1.0.5。
  2. Flutter/Dart 层：official-ota-source.mjs 对 arm64 libapp.so 的两个升级来源字符串做固定槽替换，指向本机来源。它校验整个库 SHA、字符串唯一位置、序列化长度/CID，并保持 Dart 3.11.5 canonical 字符串的长度和 hash，逐字节检查其他区域未变。这不是通用 URL 文本替换，也不修改可执行指令或固件。

原库 SHA 固定为 78214ba0e1057871315da1cee17d860415c8b913521e59afc2748e45ead64c6c；补丁包二次审计还锁定补丁库 SHA。任何宿主、Flutter 编译器、快照布局、偏移或 canonical hash 变化，都需要重新研究并验证，不能复用旧偏移。

维护官方宿主新版本

当前脚本只接受固定摘要1.0.5（201），不是“1.0.5及以上”。官网新下载文件也可能不再匹配。新输入先保存原始文件及 SHA，不修改当前白名单强行打包。

  1. 在隔离研究目录解码新宿主，与既有版本对照语音 listener、Activity、事件桥、传输管理器、消息构造器、枚举、高德接口及 OTA 队列。先确认类和语义，再确认方法签名；混淆名相同不能证明含义相同。
  2. 将确认过的输入纳入新的 version/code/SHA profile，为精确 descriptor、重复类、缺失签名和未知摘要补充拒绝测试。同步调整实际打包器版本门槛，不能只给 PROFILES 加一行。现有 HostProfilesTest.mjs 是测试入口。
  3. 审查运行时耦合：TurboAddon 的 NlpResult getter/setter、NavReflect/NativeTransfer 的字段和构造器、HostBusiness 的 wire 名称、事件 Map、线程与会话语义。构建前检查只能覆盖被列出的契约；不覆盖所有反射点。
  4. 在干净解码目录重建包装，核对原方法保留、同步 catch、Java 内部分发及 OTA 事件提前消费路径。普通包按 verify_apk 允许集核对变更。
  5. 完成随机回复→官方命令保留→自有模型→文件+业务ACK→日常功能的设备回归，再写兼容矩阵。历史1.0.4、iOS1.0.5或同名固件记录不作为新 Android 验收。

OTA 需要另一次适配判断。 官方 Dart libapp.so 的摘要、序列化字符串偏移、长度、CID、canonical hash 任一变化都会拒绝补丁。先重新研究来源路由与官方升级业务，再更新有证据的审计约束和测试；不能将旧偏移套新库。新 Java profile 成功不等于 OTA 可用。
