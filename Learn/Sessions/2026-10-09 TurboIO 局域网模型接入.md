# 目标与授权

用户已同意修改本地 [TurboIO 普通 V2 扩展](https://github.com/Turbo1123/Turbo-IO/tree/main/official-addon)，使用现有 [Windows](https://learn.microsoft.com/windows/) 模型服务，不部署证书。仅允许指定的 [HTTP](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsexceptiondomains) 地址 `http://192.168.31.101:8080/v1/chat/completions`，仍要求用户在手机本地填写认证 Key；密钥不写入源码、笔记或应用包。

模型 ID：`qwen3.8-flash-next-iq3_xxs`，由用户提供；未自行判定模型架构或供应商。

## 已知基线

用户报告：手机研究副本已安装，能登录、连接眼镜，完成一次官方问答，镜片文字与声音正常。诊断截图显示官方完成回调为 1。自有模型链路尚未验证。

这次是用户授权的实现与安装指导，不是经过探测和提取检查的正式课程。没有评分检查，不把操作成功误记为概念已掌握，也不据此追加复习任务。

## 计划

1. 保持默认构建只允许 HTTPS；用显式编译开关启用这一条局域网地址。
2. 对指定地址、其他地址和拒绝重定向进行测试，使用合成认证值，不调用真实模型。
3. 编译独立扩展并准备仅在本机保存、未签名的更新 IPA。
4. 用户通过 [Sideloadly](https://sideloadly.io/) 保持原账号与应用标识重新签名安装，再在手机测试。

## 安全边界

HTTP 是明文传输，认证不提供加密。只在可信局域网使用独立可撤销的 Key。不添加公网入口、不刷眼镜固件、不绕过宿主版本校验、不全局新增网络安全豁免。

## 安装失败后的更正

用户报告 `ApplicationVerificationFailed / 0xe8008001`。本地检查失败的签名包，复现了主应用资源签名不一致：原版没有 `._…` 元数据条目，新打包过程引入 3,132 项，签名资源清单引用了其中 3,130 项，元数据感知解包后这些文件缺失。动态库签名本身通过。本轮新归档方式存在缺陷，不是用户模型配置错误。

修正归档方式，排除资源叉与扩展属性侧文件；源应用、实际资源、扩展和应用标识保持不变。新增回归使用真实本机签名与解包流水线，旧流程失败、新流程通过；6 项打包与网络配置测试全部通过。修正版应用文件（排除元数据条目）与旧包逐字节相同。

本机生成修正版后，由用户重新签名安装；用户已确认可以正常打开，签名安装故障闭环。用户随后确认原先连错 Wi-Fi，纠正后 API 测试通过；切换自定义模型并提问后，确认镜片完整回答、声音正常，Windows 上的 [Strata](https://github.com/Niko1221/Strata/blob/main/README.zh-CN.md)出现对应请求或生成活动。单轮自有模型问答链路闭环；自动刷新已登记修正版缓存，用户拔线确认无线发现，并手动触发后台刷新后确认重新安装和模型 API 测试通过；无人值守到期前调度、连续对话、断网恢复和问答后台稳定性仍未验收。诊断产物仅保留在明确标注的本机 build/signature-debug 目录，不公开账号、描述文件或签名身份。
