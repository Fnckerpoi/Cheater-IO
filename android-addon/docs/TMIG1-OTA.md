# Android 1.0.5 (201) TMIG1 official OTA adaptation

The official guarded and preparation profiles select fixed TMIG1. The old active sender retains TAP1 static APIs and explicitly rejects any non-TAP1 package. No host allowlist, Dart source routing slot, or business module changes are required by this implementation.

TMIG1 identity: ZIP 8,824,204 bytes, SHA-256 f1d3616cfde5d128a9b60baab420559e38d19300838b0b87ceb1010f2ac5c940; AP 7,373,064 bytes, SHA-256 30522ac7d27a6750274fc2441cf7dd8f3d0ba70d43671e5595b411daa3b135f8. OtaProfile.java contains the complete 16-member Size/SHA-256 allowlist copied from official-addon/tmig1-edition/ExperimentalOTA.m. The manifest itself has a fixed SHA-256 and all 15 payload rows must match name/size/MD5 and exact field set. Its pinned bytes also bind row order, burn paths, addresses and modes. Original stock ZIP and TAP1 are rejected by TMIG1.

The official source accepts only Android S3 firmware queries for 01.00.04.0012 or 01.00.05.0005, and supplies target 0100050005 / 100050005. Only the unique Strix_OS_1.0.5.5 prepared directory is accepted. Directory snapshots retain NOFOLLOW opens, member identity and hash checks, and outgoing bytes must equal the private frozen snapshot. Root and ancestor identities/non-symlink status are rechecked around enumeration and every read, followed by a final exact member-set check. SecureDirectoryStream providers use handle-relative member attributes and opens. Windows JBR tested here exposes neither SecureDirectoryStream nor fileKey; its fallback compares creation time and root modification time. This is best-effort replacement detection, not equivalent to iOS openat: creation-time collisions, ABA replacement between checks, and filesystem/provider timestamp semantics remain limitations. Fixed per-member SHA-256 and private byte snapshots still bind every outgoing byte. No claim of atomic path identity is made for the fallback.

Authorization uses TMIG1 and lasts at most 15 minutes before Mode2 starts. Fresh version, battery, space and idle evidence, foreground service and peer binding remain required. Migration may start from Strix OS 1.0.4.12 or 1.0.5.5; completion requires fresh 1.0.5.5 boot-confirmed/idle responses after start or process recovery. All 15 payload names, including bt_controller.bin, are permitted only as exact requested slices. AP coverage is a transfer observation, not evidence that all payloads installed.

The START_INTENT journal commits peer hash, profile and candidate SHA before Mode2. Unknown/legacy candidate journals cannot be released by TMIG1. Process restart does not unlock. After natural reboot/home, explicit readback and manual TMIG1 menu/function inspection are required. Never infer success from a reconnect, progress counter, the same version number, or the former TAP1 TEST label. No automatic retry/resume is added.

Run test-tmig1-ota.ps1 with -JavaBin (JDK bin directory), -TmigZip, -TapZip and -StockZip. It compiles pure Java tests in a new temporary directory and runs both original TAP1 and new TMIG1 suites. Directory symlink tests require Windows symlink privileges; failure is reported, never silently skipped. Node regression commands: node android-addon/tests/OtaHooksTest.mjs; node android-addon/tests/HostProfilesTest.mjs; node android-addon/tests/OfficialOtaSourceTest.mjs. The last command requires the unmodified pinned host libapp.so under build/host-105.

Hardware acceptance remains separate: inspect real query shape and 16 extracted members; capture official Mode2/type3/5/6/7 timing and requested payloads; verify natural reboot, target boot status and TMIG1 functions. Notification, synchronization, navigation, music and reading compatibility are independent post-flash checks. OTA success alone does not certify all phone business features. The official automatic-update setting must be switched off before the controlled trial; no undocumented preference key is guessed by this adaptation.
