# SCADA 近距温度与气压实验：零基础中文手册

这套实验的效果是：携带手机靠近传感器时，眼镜显示温度与环境气压；离开后退出显示，重新靠近可再次显示。**手机是近距扫描器**，判断的是手机与传感器的接近程度，不是眼镜与传感器的距离。手机放在桌上、只戴着眼镜走动，不能据此测试近距进出。

用户已反馈：在该用户、该设备组合的实验中，离开后眼镜回首页，回到近距后无需手动确认即可再次显示，效果符合预期。这是这一次设备实验通过的反馈，**不是全部手机、眼镜、固件和后台场景的认证**，也不代表本文重新完成了全套验收。旧验收文档保留了当时“待真机验证”的历史记录；本次反馈只补充上述进出体验，不替代其中全部测试项目。

## 1. 先看懂三台设备各做什么

| 设备 | 它做的事 | 你需要知道的事 |
| --- | --- | --- |
| ESP32-C3 开发板 + BMP280 模块 | 采集温度、气压，将加密数据通过低功耗蓝牙（BLE）广播 | 固件不内置你的实验密钥；需事先配置。BMP280 **没有湿度功能** |
| Android 手机 | 扫描广播，验证与解密数据，用信号强弱判断是否靠近，再把有效读数发给已连接的眼镜 | 距离判断发生在手机上；需要权限、后台设置和主动启动 |
| 兼容的 RayNeo 眼镜 | 沿用宿主 App 的连接显示事实文字 | 本功能不调用 AI、不录音，也不使用云端转写来生成读数 |

眼镜文字包括“SCADA”“温度：… °C”“环境气压：… Pa”。Pa 是帕斯卡，表示气压；它不是天气预报中的海平面修正气压。温度显示两位小数不等于测量精度达到 0.01 °C；模块受板卡发热、摆放和环境影响。

这是单传感器研究实验。BLE 广播不需要把 ESP32 与手机在系统蓝牙页面配对；眼镜仍需通过宿主 App 正常连接。广播经过 AES-128-GCM 加密与认证，但这不等于开发板存储已启用加密；请保护实体设备。

## 2. 准备清单与接线

准备下列物品，第一次最好由熟悉硬件的同伴协助：

- 一台兼容的 Android 手机。现有安装资料的基础要求是 Android 10 及以上、arm64；不代表每个品牌和版本都已验证。
- 已能通过兼容研究宿主连接的眼镜，手机和眼镜有足够电量。记录自己的眼镜型号和固件版本。
- 一块 ESP32-C3 开发板、一块支持 3.3 V 的 BMP280 I2C 模块。确认购买的是 BMP280；BME280 不是本固件的替代品。
- 可传输数据的 USB 线、稳定电源、连接线，以及用于首次写入固件和配置的电脑。只有充电功能的 USB 线不能用于配置。
- 卷尺或地面距离标记，用于现场标定。
- 已获准使用、包含当前 SCADA 功能的可信测试 APK，以及属于这块传感器的实验密钥和设备前缀。

### 按实际板型接线，不要按颜色或排针位置猜

以下表格来自 [ESP32 固件 README](../../esp32-scada/README.md)，**仅适用于其列出的 ESP32-C3-DevKitM-1 接线方案**：

| ESP32-C3-DevKitM-1 引脚标识 | BMP280 模块引脚 |
| --- | --- |
| 3V3 | VCC / VIN（模块必须兼容 3.3 V） |
| GND | GND |
| GPIO4 | SDA（数据线） |
| GPIO5 | SCL（时钟线） |

1. 先断开电源，再接四根线；核对板上印字，不按照片左右顺序照搬。
2. 使用带 I2C 上拉电阻的 BMP280 模块。当前固件依次探测地址 0x76、0x77，要求 BMP280 芯片身份为 0x58。
3. 接好后请同伴核对供电、电平和接线，再通电。不要把 5 V 接到只支持 3.3 V 的接口。
4. 如果你拿的是 SuperMini、其他 C3 板或不同封装模块，先核对该板原理图、引脚说明与固件配置。GPIO4/GPIO5 不能泛化成所有板子的固定接法；不确定就暂停通电。

首次写入固件和配置的具体命令以固件 README 为准。初学者可以请同伴完成，再让对方交代板型、供电、固件版本和是否已配置成功；本文不要求你先学会编译。README 中的串口号只是当时环境示例，请选电脑实际识别的端口，不要照抄。

## 3. 如何拿到正确、安全的手机测试程序

本手册不附带或发布 APK、SDK，也不把仓库源码当成可以直接安装的手机程序。当前扩展针对 **RayNeo 1.0.5（201）研究宿主**；看到相似版本名或新的官方版本，不等于可以替代。普通官方 App 也不一定包含 SCADA 入口。

1. 从项目正式说明指向的发布渠道或可信实验提供方获取测试 APK。先确认该构建明确包含本手册的 SCADA 字幕与自动重入功能，不要从陌生群文件、网盘转发包或广告下载站安装。
2. 请提供方同时给出版本/构建标识、文件 SHA-256 校验摘要、签名证书摘要、适配的手机/眼镜条件及回退方法。校验摘要应从可信渠道取得；有一串摘要本身不证明来源可信。需要时请同伴帮你比对。
3. 对照 [Android 扩展说明](../README.md) 和 [安装说明](INSTALL_AND_FLASH.md) 核对基础条件。那里介绍的历史公开 APK 不自动代表已包含当前 SCADA 改动，也不要把其中刷眼镜固件的流程当成本实验必做步骤。
4. 安装前先确认旧 App 的备份、数据保留和恢复安排。若出现“签名冲突”“应用未安装”，停下来核对包身份与签名；不要为了继续而直接卸载旧 App、清数据或反复安装。
5. 正常打开宿主并连接眼镜，进入 Turbo IO 页面，确认能找到“SCADA 传感器 · 本机实验”。找不到时先核对构建，不要靠刷固件寻找入口。

**关于自己签名：** 源码自行组装需要符合构建要求的原始 1.0.5（201）宿主、开发工具和适用许可，再用自己的签名签署。同包名但签名不同的 App 通常无法覆盖安装；自己签名也不能冒充官方或覆盖别人签名的版本。后续更新需保持相同签名。初学者请使用已核验的测试安装路径，或让同伴安排独立测试设备/经审查的独立包身份；**不需要、也不应该索取维护者的签名私钥或 keystore**。APK 签名密钥与下面的传感器 AES 密钥是两回事。

## 4. 先处理连接、后台与系统权限

首次建议保持手机亮屏、App 在前台，先跑通，再试熄屏。

1. 打开手机蓝牙和系统“位置信息”，在宿主中确认眼镜已连接。先结束眼镜导航、阅读、音乐、云端字幕、显示测试或传输等可能占用显示通道的任务，让眼镜回到首页。
2. 进入 Turbo IO 底部“设置” → “后台运行”，开启“允许活动任务在后台继续”。这个开关只是允许你主动启动的任务继续运行，不会自动开始扫描。关闭开关会停止当前扩展任务。
3. 返回 Turbo IO 首页，进入“SCADA 传感器 · 本机实验”。后续按 Start 时，按系统提示授予权限。每轮权限提示处理完后，回到页面再点一次 Start；不要假定已自动开始。

| 手机系统 | 需要留意的权限 |
| --- | --- |
| Android 10–11 | 位置权限；当前扫描流程还要求后台位置权限，以支持熄屏扫描。系统可能要求去应用权限设置中选择“始终允许” |
| Android 12 及以上 | 附近设备扫描、精确与近似位置权限；位置选择“精确”，仅允许近似位置不够 |
| Android 13 及以上 | 还会请求通知权限，建议允许，以便看到运行状态和停止入口 |
| Android 14 及以上 | 仍需在 App 界面可见时启动；若提示前台服务被系统拒绝，返回前台核对权限与测试构建兼容性 |

手机系统“应用信息”中检查该 App 的权限、通知和电池/后台活动设置。不同品牌菜单名称不同；若被系统省电策略终止，可按本机说明允许其后台活动，再验证。App 不会自动取消电池优化，不保证永不被杀，也不会在进程被杀后自动恢复扫描。当前使用低延迟扫描，持续运行会耗电，不能称为“极省电”。

## 5. 填好传感器配置，只需保存一次

### 两端必须是同一组值

ESP32 首次配置时生成属于该设备的一组随机凭据；手机必须填入完全对应的值：

| 手机输入框 | 填什么 | 常见错误 |
| --- | --- | --- |
| AES-128 key (32 hex characters) | 16 字节密钥，写成 **32 个十六进制字符** | 把“32 字符”误当“32 字节”，复制多了换行或标点 |
| Nonce prefix / device ID (16 hex characters) | 8 字节设备前缀，写成 **16 个十六进制字符** | 只改手机、不改传感器，或与另一块板的前缀混用 |
| Entry RSSI threshold dBm | 进入阈值，范围 -100 到 0；初次可用默认 -70，再现场标定 | 把它当成距离米数；漏填负号 |
| Exit hysteresis dB (1–30) | 退出回差，范围 1–30；默认 6 | 填成 -6，或把回差当距离 |

十六进制只使用 0–9、a–f（大小写均可），不要加 `0x`、引号、空格分组或中文标点。不要用协议文档的公开测试向量作为真实设备密钥。凭据通过可信的私密渠道交接，不发到公开聊天或工单。

1. 如果已开始扫描，先按 **Stop SCADA BLE scan**。扫描中或准备启动时不能保存配置。
2. 首次完整填写两项凭据和两项距离参数，按 **Save encrypted lab provisioning**。它保存手机端配置，不会通过蓝牙替 ESP32 配置，也不会启动扫描。
3. 保存成功后密钥和前缀输入框会主动清空；重新打开页面也不会回填。**输入框空不代表没有保存。** 数据使用 Android Keystore 加密保存；后续直接按 Start 即可，不要每次重新生成凭据。
4. 查看状态里的 Threshold 和回差是否符合本次设置。此页面状态不是持续自动刷新的，等待后按 Refresh 查看。
5. 以后只改距离参数时，可以将密钥和前缀留空，以保留已存值；但**阈值或回差留空会采用默认 -70 / 6，不是保留上次值**。请把想使用的两项距离参数都明确填写后再 Save。

保存报错时不要假定保存完成，也不要直接开始实验；停止扫描后检查格式和范围，再重试，必要时交给同伴核对。

不要发送配置页截图。当前实现的状态区 **Device ID 可能直接显示设备前缀**，即使密码输入框已空也可能泄露；反馈问题时只摘录错误短句，遮掉 Device ID、前缀、密钥、设备标识与私人通知。

## 6. 看懂按钮，避免反复乱点

| 页面上的真实文字 | 实际作用 | 什么时候使用 |
| --- | --- | --- |
| Save encrypted lab provisioning | 保存凭据与距离参数；不启动扫描，不替开发板配对或写配置 | 首次配置、停止后修改参数 |
| Start SCADA BLE scan | 用户主动申请前台扫描服务，读取配置和防重放记录，通过后扫描 BLE | 准备好配置、权限和连接后；请求权限结束后需再次按 |
| Stop SCADA BLE scan | 停止扫描和本地字幕提交，释放扫描服务占用，并请求关闭自己的字幕会话；不删除凭据 | 结束实验、修改配置、排错前 |
| Refresh sensor status | 把当前状态重新显示到页面 | 等待几秒后看进度或错误；它不会重扫、重连、保存或强制刷新镜片 |
| I verified the lens is clear | 在对应会话处于停止/结果不确定状态时，记录你亲眼确认镜片已退出，并释放该会话的本地占用 | 故障恢复时确实看清镜片已退出后；不是清屏命令，也不是正常重入的必点按钮 |
| Clear encrypted provisioning | 停止扫描并移除手机保存的传感器凭据；保留防重放历史 | 有明确换配置需要时；不要作为常规修复步骤 |

通知里的“停止所有扩展任务”和后台页的停止按钮会停止所有当前扩展后台任务，影响范围大于 SCADA 页的 Stop。Stop 或关闭手机页面本身都不能作为镜片已物理清屏的证明；离开手机页面也不等于停止扫描。

## 7. 第一次跑通：靠近 → 离开 → 再靠近

1. 给已接好线、已配置的 ESP32-C3/BMP280 通电，让它保持固定位置。手机与眼镜保持连接，眼镜当前没有别的显示任务。
2. 携带手机站到传感器附近，在 SCADA 页按 **Start SCADA BLE scan**。若弹权限提示，处理后回到页面再按一次。
3. 稍等后按 **Refresh sensor status**。看到 `Low-latency scan armed` 说明扫描已启动；`Foreground lease active` 表示有前台扫描服务占用。它们不等于眼镜一定已显示。
4. 等待连续三个通过认证、防重放检查且满足进入阈值的有效数据包，再观察眼镜。三个包不是三秒，也不是任意三个蓝牙信号；启动眼镜显示还需要连接与会话准备时间。
5. 亲眼检查镜片上出现温度 °C、环境气压 Pa。`SCADA caption active; lens visibility unverified` 表示软件已进入显示流程，但镜片可见性仍需你观察。
6. **带着手机**离开传感器，越过标定的退出范围。眼镜应退出 SCADA；本次用户已观察到回首页。若远处收不到包，走的是无有效近距数据后的过期处理，不能把走出某个距离与某个固定秒数画等号。
7. 正常退出后，先留出至少约 **8 秒的重入冷却时间（cooldown）**，再带手机回到近距，保持稳定并等待新鲜有效包与显示准备。过早回来时也应继续等待；不要不停按 Start、Stop 或人工确认。
8. 正常离开后的自动重入，还要求上一会话符合重入条件、关闭提交成功、同一眼镜保持连接、显示通道可用。此用户此设备的反馈是无需按人工确认就能重新显示；若你的组合不满足条件，按下面的恢复步骤排查。
9. 完成后按 **Stop SCADA BLE scan**，观察镜片确实退出，再结束供电。下次凭据未改且状态正常时无需重新填写。

### 8 秒、10 秒分别是什么

- **8 秒：** 正常退出后允许重开会话的最短冷却门槛之一，从软件记录的关闭请求时刻计时。它不是回到近处后必须正好等 8 秒，也不是保证 8 秒后必定显示，更不是眼镜已清屏的证明。
- **10 秒：** 从最后一条被接受的近距读数采集时刻起计算的新鲜度期限。到期任务执行时，软件拒绝旧事实并请求关闭字幕；已经退出后的远距包、重放包和无效包不会把旧读数续期。
- Android 调度、手机深睡、断连和 SDK 排队会影响镜片实际退出时间。软件发送关闭请求或 SDK 返回成功，都不等于镜片收到并已清除。**不能承诺硬实时清屏。**

状态中的 `requested` 是已请求关闭，`uncertain` 是结果未知，`confirmed` 是用户人工确认。`previous lens clear unverified` 表示上一会话的镜片退出未获自动验证；不要为了消除提示而谎点确认，也不要把自动重入成功倒推成上一会话有设备清屏回执。

## 8. 把“约一米”调成适合现场的范围

RSSI 是信号强弱，不是测距尺。一般 -60 dBm 比 -80 dBm 强，但人体遮挡、口袋、墙壁、反射、天线方向、手机型号都会改变结果。默认 -70 dBm **不代表精确 1 米**。

1. 先固定传感器、手机朝向和携带方式，在地面标出 0.5 米、1 米、1.5 米及希望的退出位置。距离从手机到传感器算。
2. 先用默认进入阈值 -70、回差 6 试跑，在每个位置停留观察，记录能否稳定显示、是否来回闪断、离开后是否退出。换到实际放口袋的方式还要重试。
3. 请熟悉工具的同伴协助记录 RSSI：验收手册建议每个距离至少 30 个样本、至少 3 轮，比较中位数与波动范围。当前页面不是完整 RSSI 采样工具，不要以为多按 Refresh 就完成了这项采样。
4. 需要更容易进入时，可试更负的阈值，例如从 -70 改到 -75；需要更靠近才进入时，可试 -65。一次只做小幅调整，每次先 Stop，填写参数后 Save，再 Start 复测；数字只是调参示例，不是推荐的一米值。
5. 进入需要三个连续合格包。已进入时，RSSI **低于“进入阈值减回差”**才退出；等于退出边界仍保持近距。例如 -70 和 6 的退出条件是低于 -76 dBm。回差可减少边缘反复进出，但也会扩大退出范围。
6. 反复验证“近处稳定出现、远处稳定退出、再次靠近能恢复”。环境或手机变了重新标定；如果始终找不到稳定范围，就记录该场景不满足要求，不要写成精确测距成功。

## 9. 常见问题：按顺序恢复

先按 Stop，再按问题表处理；需要观察自动进出时保持扫描运行，不要把正常冷却误当故障。重试前结束其他显示任务，确认镜片实际状态。

| 看到的现象或提示 | 先检查什么 | 怎样继续 |
| --- | --- | --- |
| 找不到 SCADA 入口 | 是否装了包含当前功能的可信测试构建 | 核对构建标识；不要安装随机 APK 或盲目刷眼镜固件 |
| `Enable background activity...` | Turbo IO 的后台运行开关是否开启 | 设置 → 后台运行 → 允许活动任务在后台继续，再回前台启动 |
| `permission denied` 或启动后只弹权限 | 附近设备、精确位置、后台位置及系统位置开关 | 按系统版本补齐，回页面再按 Start |
| `BLE scanner could not start` | 蓝牙开启、权限正常、服务未被系统拦截 | 修正后从前台重试；仍失败记录错误短句与手机系统版本 |
| `Invalid provisioning or settings; nothing was started` | 是否扫描未停、凭据字符数不对、参数超范围 | Stop 后按第 5 节核对两端配置再 Save；不要把该提示当成保存成功 |
| `Cannot start: provisioning or saved replay state is invalid` | 凭据或持久化防重放记录可能异常 | 停止重试，把脱敏错误交给同伴检查；不要清 App 数据或重置计数器绕过保护 |
| valid 一直不增加，rejected 增加 | 电源、接线、真实 BMP280、两端密钥与前缀是否一致 | 私下核对，不发配置截图；传感器读取失败时固件可能不广播 |
| replayed 增加 | BLE 会重复发送相同加密包与计数器，重复包被拒绝可能正常 | 看是否也不断收到新 valid；若一直只有旧包，请同伴检查固件与计数器，不要重置历史 |
| valid 在增加但眼镜没内容 | 手机是否达标近距、眼镜连接、显示通道是否被占用 | 携手机靠近并保持；结束导航/云字幕等任务。仍失败则 Stop，恢复通道后重试 |
| 刚离开又回来不立即显示 | 是否还在 8 秒冷却、是否收到新鲜合格包 | 等待冷却和准备；不要用人工确认加速正常重入 |
| `waiting for display owner`、busy 或持续 uncertain | 其他显示任务、断连或上次会话未退出 | Stop，恢复连接，结束其他显示任务。亲眼确认镜片已回首页/旧字幕消失后，才按人工确认，再 Start |
| Stop 后文字还在 | 关闭请求不等于物理清屏，连接或排队可能异常 | 确认手机已 Stop；按眼镜正常退出操作回首页，恢复连接。看到旧字幕确实消失后才按人工确认；仍异常就保留脱敏记录暂停实验 |
| 熄屏后不工作、App 被杀 | 系统电池优化、后台限制和权限 | 回到前台核对状态与设置，再主动 Start；先短时测试熄屏，不承诺长期后台稳定 |
| 数值不变或气压不像天气 App | 环境本身稳定、传感器发热，或比较了海平面气压 | 看新 valid 是否持续增加；不变数值也可以是新读数。不要寻找不存在的湿度字段 |

人工确认只能覆盖你本次亲眼观察。若镜片仍有旧文字、你没有戴眼镜或连接状态不明，就不要点 **I verified the lens is clear**。按钮不会替你清屏，也不会关闭别的功能所占用的会话。

## 10. 别用清空数据来“修好”它

开发板的 NVS 是掉电后仍保留配置的存储区，其中保存了凭据和发送计数器保护记录。手机也保存已接收计数器的防重放历史。它们用于防止旧广播被当成新数据，并保护加密所需的唯一编号。

- 不要随意执行 `erase_flash`、擦除 NVS、恢复出厂设置或清 App 数据；也不要因信号弱或重入慢而重新初始化计数器。普通重启通常不需要重新配置。
- ESP32 配置是一次性的，固件会拒绝直接覆盖已有凭据。手机的 Clear 按钮只清手机凭据，不清开发板，也不删除手机防重放历史；重新填回旧凭据不能借此接收旧包。
- 若确实擦除了开发板 NVS，或更换了板卡，须由熟悉流程的人生成**全新的密钥和全新的前缀**并在两端匹配配置。不能在计数器归零后继续用旧密钥加旧前缀，否则会重复使用加密 nonce。
- 手机报告防重放状态损坏时，保留现有状态请同伴处理；不要把清空保护记录当成通用修复。

## 11. 如何记录结果而不泄露秘密

用简单文字记录：手机型号与 Android 版本、测试 App 构建标识、研究宿主 1.0.5（201）、眼镜型号/固件、板型/传感器型号、进入阈值/回差、手机摆放方式、是否亮屏、每轮靠近/离开/再靠近的实际表现。可写“在这台手机和这套设备上，连续三轮离开后回首页、再靠近自动显示”，不要写“所有设备已通过”。

若拍镜片退出过程，区分“手机提示已请求关闭”与“亲眼看到镜片回首页”的时间，不只拍手机状态。录像避开人脸、账号和私人通知；不发送 AES 密钥、前缀、配置截图、完整设备序列号、蓝牙地址或原始配置终端记录。需要排错时只提供脱敏错误文字与上述环境信息。

## 12. 术语小词典

| 术语 | 白话解释 |
| --- | --- |
| SCADA | 本项目中传感器采集与显示实验的名称；这里不是完整工业控制系统 |
| 宿主 App | 承载 Turbo IO 扩展、连接眼镜的手机应用 |
| APK / SDK | APK 是可安装的 Android 程序文件；SDK 是开发工具与接口，不是给眼镜安装的普通应用 |
| BLE 广播 | 开发板向周围周期性发送短数据；扫描这块板无需蓝牙配对 |
| AES 密钥 | 解密并验证实验数据的秘密值；与 App 签名密钥不同 |
| prefix / nonce | prefix 是设备配置的前缀；与计数器组合为每份加密数据的唯一 nonce，不能随意复用 |
| counter / 防重放 | 数据编号 / 拒绝已收过的旧编号，避免把旧数据当成新数据 |
| RSSI / dBm | 无线信号强度 / 它的单位；不是米数 |
| 阈值 / 回差 | 达到某信号强度才进入；退出用另一条较弱边界，减少反复跳动 |
| cooldown | 退出后的重入冷却等待；不是镜片清屏确认 |
| 前台服务 / lease | 系统中可见的运行任务 / 当前扫描任务占用的服务资格 |
| NVS | 开发板断电后仍保存配置与计数器记录的存储区 |
| SHA-256 / 签名 | 文件完整性指纹 / 安装包发布身份与更新关系；两者用途不同 |
| requested / uncertain / confirmed | 请求已发出 / 结果未知 / 用户亲眼核实后确认 |
| °C / Pa | 摄氏温度 / 帕斯卡气压单位；BMP280 不测湿度 |
