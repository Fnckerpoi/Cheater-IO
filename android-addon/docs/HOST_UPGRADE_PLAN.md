# Android 宿主升级维护执行计划

## 目标与范围

外置宿主 profile、生成只读差异审计报告、统一普通与 Windows 打包器的失败关闭门禁。当前回归基线为官方 Android 1.0.5（201）；1.0.4（195）仅保留历史身份记录。V1.0.7 在取得原始 APK 并完成审计前不登记为受支持版本。

本次不操作手机或眼镜，不签名、安装、刷写，不改变实验 OTA 的授权或结果保护机制。

## 阶段任务与验收

| 阶段 | 实现 | 产出 | 验收 |
| --- | --- | --- | --- |
| 1 | 梳理宿主符号、运行时反射、smali 与原生 OTA 依赖 | 依赖清单与准入契约 | 区分自动检查和人工项 |
| 2 | JSON profile、严格加载与受支持 adapter | profile 与加载测试 | 历史版本、未知/未批准/撤销版本失败关闭 |
| 3 | 隔离反编译与完整差异检查 | JSON/Markdown 报告及审计测试 | 未知 APK 可审计，报告不赋予打包资格 |
| 4 | 两打包入口共用准入、隔离工作目录与收据 | 共用构建模块、入口改造及测试 | 完整检查前无宿主补丁写入，失败不发布 APK |
| 5 | 正反例回归、关键改动复审 | 验收报告 | 不将 fixture 测试表述为真实 APK 或真机验收 |
| 6 | 支持矩阵和新增/撤销版本流程 | 维护指南与交付记录 | 清楚说明仍需人工审计和真机验证的边界 |

## 已确定的设计约束

- 两条打包入口共用相同准入判断。未知 SHA 不可通过版本号替代匹配。
- Profile 只保存数据；可执行补丁留在代码，adapter 必须显式注册。复制旧 profile 并更换哈希不会自动获得新版本支持。
- 批准构建与真机验证是两种状态；迁移既有基线不新增或扩大历史验收声明。
- 审计命令可分析未知 APK，但不能修改或批准 profile。候选定位不等同语义兼容。
- 仅比较方法签名不能覆盖运行时语义、重签后厂商服务和长期稳定性。
- 原生 OTA 来源修改依赖 libapp.so 精确哈希与字符串位置；既有精确校验继续保留，不随 profile 外置而放宽。
- 现有构建目录可能已被 hook 改写，新的审计与打包必须使用全新隔离目录。

## 执行分工

- 依赖审查：只读梳理宿主与 OTA 绑定，回报路径和证据。
- Profile/审计实现：独占 profile、宿主校验、审计命令及对应测试。
- 构建实现：独占两条打包入口、共享构建门禁及对应测试。
- 调度复审：复核关键改动，独立运行测试，维护文档与验收说明。

最终测试证据和限制记录于配套验收文档，不以本执行计划代替验收结果。
